```
┌─ 每一轮循环 ────────────────────────────────────────────────┐

│ 6. 你反馈：「太暗 / 移动太慢 / 弹道太难 / 这里报错」           │
│ 7. 我改；如果是纯数值，你在编辑器里自己改一行也行              │

```

**一轮循环的耗时**：纯规则改动（几分钟）→ 我改完直接跑测试；表现层改动（十几分钟）→ 我改完截图给你看。

**你实际要动手的部分**（合计大概 1-2 小时，一次性）：
1. 装编辑器（或直接用我下好的 `tools/godot/` 里的绿色版，双击即可）；
2. 装导出模板（要出 Web 包时才需要）；
3. 用编辑器打开项目、按 F5 试玩；
4. 觉得哪里不对，用文字告诉我（不需要你会改代码）。

## 4. 实测中我真的踩到并修掉的坑（说明"能跑"意味着什么）

这些都是我写完代码后**真跑起来才发现的**，不是纸面推演：

| # | 现象 | 真实原因 | 修法 |
|---|---|---|---|
| 1 | 3D 场景里**敌人全部不可见** | 我的相机方向向量写成了 `+sin(pitch)`，相机跑到**地面下方 17 米**，从下往上穿地形看 | 改成 `-sin(pitch)`，相机变到 +18.5 米 |
| 2 | 地板是一片**漆黑** | 顶面绕序让法线朝下，光照算不到 | 改绕序 / 改用 unshaded 地板 |
| 3 | 地形**挡住了所有单位** | 地形是"薄板 + 侧壁"，从上方看能看进壳体内部，且平面挡住了单位 | 每格只留顶面 + 关闭背面剔除 |
| 4 | 我的**测试用例自己算错了**（破甲 3+2 精力，我写成 7‰ 而不是 7000‰） | 单位混用（点 vs 千分比） | 测试立刻报红，改成显式单位 |

**这 4 条的共同点**：静态读代码都"看起来对"，只有真的跑起来才暴露。所以我的流程是**写完必跑**。

## 6. 关于"我能不能自己装 Godot"——这条要你点头

**我已经做了**：下载绿色版编辑器到 `E:\新建文件夹\tools\godot\`（免安装，删掉即可，不写注册表、不改 PATH），并用它跑通了测试和截图。

**我还没做**：把导出模板（1.19 GiB）**安装到你的全局配置目录**（`%APPDATA%\Godot\export_templates\`）。理由：那是你机器的全局状态，且只有在"要出 Web 包"时才需要。
如果你希望我现在就装，跟我说一声即可；不想装也完全不影响开发（桌面版运行、headless 测试都不需要它）。

**为什么建议保留 `tools/godot/`**：它让"我改完代码 → 立刻自己验证"成为可能。如果你不希望它在工作目录里，我可以移到别处或删掉——但那样我就只能"写完不验证"，交付质量会明显下降。
