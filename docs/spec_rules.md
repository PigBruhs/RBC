> ## 仍然有效、后续代码必须遵守的部分
>
> 1. **取整三件套**：伤害 `floor`、倍率连乘 `round_half_up`、命中率 `ceil` 并钳到 [1%, 99%]。不得混用。
> 2. **伤害公式** `D = (力量 - 护甲) × (1 - 物抗)`，物抗为**乘算真减伤**（`res_mode = MULTIPLY`）。
> 3. **五档离散抗性** 无/低/中/高/免疫 = 0/200/400/800/1000‰；脏档位钳到最近档。
> 4. **双池规则**：只有力量池归零才阵亡；护甲池归零只失去减免；溢出伤害不跨池转移。
> 5. **破甲线**：定值、无视物抗与护甲、只削护甲池、不造成击杀。
> 6. **全整数千分比域 + 禁浮点比较**；32 位 LCG 可复现随机（`RngService`），同 seed 序列可复现。
> 7. **物抗 / 魔抗不可加点**；魔抗至今不参与结算。
> 8. **分层铁律** `view → ai → core`：core 全部 `RefCounted`，不 `extends Node`、不 `get_node()`。
> 9. **同一算法全局只有一处实现**；坐标用 `Vector2i`；"格数"一律曼哈顿距离。
>

### v1.2 三条最重要的实算结论（先看这三条）

1. **概率命中常态化**：`D = (P−A)×(1−R)`，五档使 `(1−R) ∈ {1.0, 0.8, 0.6, 0.2, 0}`，于是「差值 1 / 差值 2 打低抗 / 差值 3 打中抗 / 差值 1~4 打高抗」都会落进 `0<D<1`。8 原型平地 64 组中 **8 组（12%）** 触发（v1.1 为 0/64），命中率 20%~80%（§2.7）。
2. **五档等效耐久是独立的乘法旋钮**：无=×1.00 / 低=×1.25 / 中=×1.67 / **高=×5.00** / 免疫=不可击杀。而升级每级只 +3 点属性（新尺度下约 ×1.2~×1.5 耐久）→ **档位用来表达兵种身份，不能当成长曲线**（§2.7、§9.4 MR1）。
3. **`高`（0.8）档在 4v4 里过强**：石肤守卫（A=9、高抗）被同尺度攻击者击杀需 **7~15 回合**（其他原型 2~4 回合），直接冲垮「单场 3-6 回合」目标（§9.2 C9、§10.6）。v1 普通关卡若要用 `高` 档，必须同时压低其力量池或护甲（§9.4 MR2）。

## 0. 术语与全局约定

| 术语 | 含义 | 记号 |
|---|---|---|
| 力量 | 攻击力，**同时是力量池上限**（唯一击杀途径） | P / P_max / P_cur |
| 护甲 | 力量攻击的减免项，**同时是护甲池上限**（可被破甲剥夺） | A / A_max / A_cur |
| 物抗 | 力量攻击结算中的**固有抗性档位**（五档离散枚举，内部千分比整数；**不可加点**） | R / `phys_res` |
| 魔抗 | v1 预留字段，不参与任何计算（同样是五档枚举） | MR / `mag_res` |
| 抗性档位 | 无 NONE=0 / 低 LOW=0.2 / 中 MID=0.4 / 高 HIGH=0.8 / 免疫 IMMUNE=1.0（内部 0/200/400/800/1000‰） | `RES_NONE` … `RES_IMMUNE` |
| 破甲伤害 | 攻击护甲时造成的固定伤害 | BD |
| 精力 | 战局内资源池，可加伤、可被休息回复 | EP / EPmax |
| 休息恢复 | 休息时恢复的力量/护甲点数 | RS_P / RS_A |
| 移动力 / 射程 / 判定半径 | MP / RNG / SPL | — |
| 千分比 | 内部定点单位，1000‰ = 1.000，记作 milli | — |

1. 内部**全部整数运算**，比例量一律千分比整数；禁止用浮点比较决定任何分支。
2. 属性表的整数（如力量 9）在管线内展开为 `9000‰`。
3. 取整方向：**伤害 = 向下取整（floor）**；**比例乘法 = 四舍五入（round-half-up）**；**命中率 = 向上取整 `ceil(D_milli/10)`**。三者不得混用（v1.2 起 `D≥1` 的伤害常带小数，floor 的损耗见 §2.9）。
4. 「回合」= 先手方行动阶段 + 后手方行动阶段。
5. v1 无战争迷雾、无反击、无友军伤害、无遮挡视线。随机性只来自 `0<D<1` 的概率命中掷骰（§2.7，v1.2 起**频繁触发**，平地 8/64 配对），或可选的方案 B 小数额外 +1。
6. **v1.2 尺度假定（占位起点，C8）**：所有数值都是**占位起点**——用户尚未确定角色力量尺度，后续按比例整体放大（§13 D31）。因此本文件的一切 TTK/回合数结论都必须在 `balance_sim` 里按实际尺度重标定，而不是当作最终平衡。

## 1. 属性语义与数值域

### 1.1 四属性

| 属性 | 语义 | 建卡域（**占位尺度**，C8） | 升级可加 | 上限 |
|---|---|---|---|---|
| 力量 P | (a) 力量攻击的进攻项；(b) **力量池上限 = P** | 6 ~ 15 | 是（+1/点） | **30** |
| 护甲 A | (a) 力量攻击的减免项，用**当前值** A_cur；(b) **护甲池上限 = A** | 4 ~ 12 | 是（+1/点） | **24** |
| 物抗 R | 力量攻击结算中的**抗性档位**（五档枚举，见下表） | 五档枚举，**不存在中间值** | **否** | 枚举最大 = 免疫 |
| 魔抗 MR | v1 无魔法伤害，**不读取、不参与计算**（同样是五档枚举） | 五档枚举 | **否** | 枚举最大 = 免疫 |

**物抗/魔抗五档表（C1 唯一取值集合）**

| 档位 | 枚举 | 内部千分比 | 伤害乘数 `(1−R)` | 对纯力量输出的等效耐久 |
|---|---|---|---|---|
| 无 | `RES_NONE` | 0 | ×1.0 | ×1.00 |
| 低 | `RES_LOW` | 200 | ×0.8 | ×1.25 |
| 中 | `RES_MID` | 400 | ×0.6 | ×1.67 |
| 高 | `RES_HIGH` | 800 | ×0.2 | **×5.00** |
| 免疫 | `RES_IMMUNE` | 1000 | ×0 | **不可击杀**（C5，§11 E23） |

> **v1.2 重算**。五档是**固有属性**：升级池里没有物抗/魔抗（原文升级池只有力量、护甲、精力上限、破甲伤害、休息恢复力量、休息恢复护甲，以及远程射程/弹道判定范围），所以玩家**永远无法改变**任何单位的物抗档位。存档与数据表存枚举名（或等价的 0/200/400/800/1000 千分比整数），**不存连续值**。
> v1.1 旧值「物抗 0 ~ 600‰ 连续值、上限 600‰、`R≥1.0` 非法」**已被 v1.2 取代**：连续值域作废；`免疫` 现在是**合法档位**；只有 `DIVIDE`（备选模式）才需要 600‰ 护栏（§2.5）。

**核心建模决定（v1 默认）**：力量与护甲同时是「资源池」，且**只有力量池归零才阵亡**（`DEATH_RULE="power_only"`）：

- 力量线 = **唯一击杀途径**（打空力量池）；
- 破甲线 = **剥夺防御**（打空护甲池 → A_cur=0 → 力量伤害暴涨），**本身不造成击杀**；
- 两条线都不可替代：v1.2 占位数值下实测 64 组对局中 **5 组（8%）纯力量线完全无效**（`P ≤ A`：民兵/塔盾卫→塔盾卫、民兵/塔盾卫→石肤守卫、掷弹手→塔盾卫），必须先用破甲开罐；能打的对局里，**对高抗/高护甲目标破甲可把 TTK 缩短 30%~69%**，而对已经打得动的脆皮目标破甲**不缩短 TTK（0%）** —— AI 必须只在「打不动或打得很慢」时才花回合破甲（§10.2）。
- 池下限 clamp 到 0；溢出伤害只对本池结算，**不转移到另一池**。
- 备选 `DEATH_RULE="either_pool"`（任一池归零即阵亡）：**v1.0 曾采用，已否决** —— 破甲线会变成「第二条血条」且更快（v1.0 历史值 47/64、v1.1 数值下独立复算 36/64，两者都**无法从现存数值表复现**；v1.2 数值下未重算，因为该备选已被 C7 正式否决），且在 either_pool 语义下 3 点精力的破甲一击可清空多个原型的护甲池、直接击杀。改 power_only 后问题自动消失（§13.4）。

### 1.3 魔抗 v1 处理（C4）

存档与数据表**必须**保留 `mag_res` 档位（同样五档：无/低/中/高/免疫），但 v1 任何公式都不读它；UI 显示为灰色「魔抗（v1 未启用）」；升级池不含魔抗。**魔法伤害在 v1 只能由技能打出，而技能系统是 v2**，因此 v1 不存在任何魔法伤害来源。未来加魔法伤害时复用 §2 同一条管线，把 `R` 换成 `MR`、把 `res_mode` 的解释原样搬过去，公式结构不变。

> **v1.2 重算**：v1.1 旧值「MR 0 ~ 600‰ 连续值」已被五档枚举取代。**C5 的连带后果**：免疫档（`RES_IMMUNE`）单位在 v1 **无法被物理击杀**，而 v1 又没有魔法 → 唯一合法用法是 Boss 机制并在 v2 之前补魔法技能（§11 E23、§13 D29）。

### 1.4 「是否有独立生命值（HP）」歧义的结论

原文完全没提 HP，只说「每回合可选择攻击力量还是护甲」「休息恢复力量与护甲」。三种读法：

| 读法 | 内容 | 能否解释原文 | 判定 |
|---|---|---|---|
| R-a | **无独立 HP**：力量即生命（归零阵亡），护甲 = 防御资源 + 第二池 | 能。完整解释两条攻击线与两种休息恢复 | **采用** |
| R-b | 有独立 HP，力量/护甲只是属性 | **不能**。两条线都扣同一个 HP，区别只剩数值大小；「休息恢复力量/护甲」也失去意义 | 否决 |
| R-c | 有独立 HP，两池是「架势条」，任一条归零 = 破防（额外惩罚） | 能，但需额外定义破防惩罚，原文未提 | 否决（v2 扩展） |

**结论（与 Lead 默认方案一致）**：v1 **不引入独立 HP**，存活单位**不存在**任何隐藏血量字段，UI 上就是力量条与护甲条两条。论据：(1) 只有双池读法让「打力量/打护甲」成为有代价的选择；(2) 原文把两种休息恢复并列，说明两者都是会被消耗、需要回复的池；(3) 加独立 HP 会引出「HP 与力量池谁先归零」等原文没有的问题。

### 2.2 伪代码（力量攻击，三种 `res_mode` 共用同一外壳；**v1.2 默认 `MULTIPLY`**）

```
function resolve_power(atk, def, n):        # n = 本回合投入的精力点数 0..3
    assert def.R <= 1000                     # R>1000 才是非法；(C1) R=1000 是合法档位「免疫」
    r = def.R if def.R in RES_TIER_SET else nearest_tier(def.R)   # 脏档位 → 最近档 + warning
    p_milli = atk.P_cur * 1000 + ENERGY_POWER_MILLI * n     # 步骤 1：精力加进力量（占位起点 C8）
    h_milli = 1000 + HEIGHT_POWER_MOD * sign(atk.h - def.h) # 步骤 2：可选高低差；默认 0 → 恒 1000
    p_milli = round_half_up(p_milli * h_milli, 1000)        # 步骤 3：比例乘法四舍五入
    delta   = p_milli - def.A_cur * 1000                    # 步骤 4：减去护甲当前值
    if delta <= 0: return { damage:0, roll_percent:0, branch:"NO_DAMAGE" }  # 步骤 5：P≤A，提示切破甲
    switch res_mode:                                        # 步骤 6：物抗结算（三选一，§2.6）
        MULTIPLY: D_milli = round_half_up(delta * (1000 - r), 1000)      # (P-A)*(1-R)  ★v1.2 默认
        DIVIDE  : r_cap = clamp(r, 0, 600)   # 备选模式：IMMUNE(1000) 在此非法（除零）
                  D_milli = round_half_up(delta * 1000, 1000 - r_cap)    # (P-A)/(1-R)
        FLAT    : D_milli = delta - round_half_up(r * p_milli, 1000)     # (P-A)-R*P
    if D_milli <= 0: return { damage:0, roll_percent:0, branch:"NO_DAMAGE" }  # 免疫档必然落这里
    base = floor(D_milli / 1000); frac = D_milli mod 1000   # 步骤 7：伤害结算
    if base >= 1:                                           #   D >= 1 → 必中且「取整」（floor 损耗见 §2.9）
        damage = base; branch = "AUTO"
    else:                                                   #   0 < D < 1 → 概率命中（v1.2 下常见）
        hit_pct = clamp(ceil(D_milli / 10), 1, 99)
        damage = (rng_1_to_100() <= hit_pct) ? 1 : 0
        branch = (damage == 1) ? "HIT_OR_MISS" : "NO_DAMAGE"
    if REMAINDER_ROLL_WHEN_AUTO and base >= 1 and frac > 0:  # 可选增强（方案 B，默认关）
        if rng_1_to_1000() <= frac: damage = damage + 1
        branch = "AUTO_PLUS"
    def.P_cur = max(0, def.P_cur - damage)                   # 步骤 8：扣力量池
    if def.P_cur == 0: def.dies()                            # 步骤 9：唯一死亡判定（C7 power_only）
    return { damage, roll_percent: frac/10, branch }
```

```
round_half_up(a, b) = floor((2*a + b) / (2*b))      # a, b > 0
MULTIPLY : D_milli = floor((2*delta*(1000-r) + 1000) / 2000)          # r = 合法档位，含 1000
DIVIDE   : denom = 1000 - clamp(r, 0, 600);  D_milli = floor((2*delta*1000 + denom) / (2*denom))
FLAT     : D_milli = delta - floor((2*r*p_milli + 1000) / 2000)
```

> **v1.2 改写**：步骤 6 的默认分支换成 `MULTIPLY`；`IMMUNE` 不再触发断言，而是让 `D_milli = 0` 并在步骤 7 之前直接返回「无法造伤（免疫）」；脏档位处理由「clamp 到 600」改为「钳到最近档位」；高低差默认关闭。

### 2.3 伪代码（攻击护甲 / 破甲）

```
function resolve_armor_pierce(atk, def, n):
    damage = atk.BD + ENERGY_BD * n   # 固定值：无视物抗档位、无视护甲减免、无视己方力量、无视高低差
    def.A_cur = max(0, def.A_cur - damage)   # 只削防御，绝不造成击杀（C7 power_only）
    return { damage, roll_percent: 100, branch: "ARMOR_PIERCE" }
```

- `BD` 内部同样用**千分比整数**（表格里写 `2.5` = 内部 `2500`），显示保留一位小数。v1.1 旧值「BD 1~6 整数」已被取代：v1.2 占位表里存在 `2.5`。
- **连带规定（必须与 §12 一致）**：因为 `BD` 可以是 2.5，**护甲池 `A_cur` 也按千分比存**（`11 − 2.5 = 8.5` = `8500‰`），力量线用它算 `delta`；**力量池 `P_cur` 的扣减仍按整数点**（伤害 = `floor(D_milli/1000)`，`0<D<1` 命中则 1 点）。这条是 §10.2 混合线 TTK 可复现的前提。
- **破甲线不是免疫档的解法**（C5）：护甲池归零后单位仍存活，而免疫档单位的力量伤害恒为 0 → 免疫档在 v1 内不可被物理击杀（§11 E23）。

### 2.5 五档抗性的有界性与「免疫」语义（C1/C2 整节重写；v1.1「R→1 发散」作废）

**v1.2 默认 `MULTIPLY` 下的数学性质（这是本次改动最重要的收益）**：

| 性质 | 结论 | 依据 |
|---|---|---|
| 有界 | `D = (P_eff − A_cur) × (1−R) ≤ P_eff − A_cur`，**永不超过差值**，永不发散 | `(1−R) ∈ [0,1]` |
| 单调 | 档位越高伤害越低（无 > 低 > 中 > 高 > 免疫），「物抗」名实相符 | `1−R` 随档位递减 |
| 免疫 | `R = 1000` → `D ≡ 0` → 力量线**恒为「无法造伤」**；破甲线只削护甲池，护甲归零不致死 → **该单位在 v1 不可被物理击杀**（C5） | §2.2 步骤 6 |
| 除零 | MULTIPLY / FLAT 下**不存在除零**；只有备选 `DIVIDE` 在 `R = 1000` 时才会分母为 0 | §2.6 |

**v1.1 旧内容（已被 v1.2 取代，仅作为 `DIVIDE` 备选模式的护栏保留）**：v1.1 默认 `DIVIDE`，`R → 1` 时 `(P−A)/(1−R)` 发散（P12/A8/R=0.9 会给 40 点伤害），因此需要「L1 数据层 clamp 600 / L2 `assert(R<1000)` 断言拒绝 / L3 运行时钳制到 600 并 warning / L4 `denom ≥ 400` 有界」四层防护。**这四层现在只在 `res_mode="DIVIDE"` 下生效**：

| 层 | 处理 | 触发条件 |
|---|---|---|
| L1 数据层 | 建卡/数据表只允许五档 `{0,200,400,800,1000}`；`DIVIDE` 模式下额外 clamp 到 ≤600 | 一切写入 |
| L2 断言层 | `assert(R ≤ 1000)`；**`DIVIDE` 模式下 `R = 1000` 非法（除零）**：开发构建断言失败、发行构建拒绝读档 | `R > 1000`；或 `DIVIDE` + 免疫档 |
| L3 钳制层 | 脏档位（如 350‰）钳到**最近档位**（350 → 400）并记 warning；`DIVIDE` 模式下再 clamp 到 ≤600 | `R ∉ RES_TIER_SET` |
| L4 有界层 | MULTIPLY 天然有界（见上表）；`DIVIDE` 下 `denom ≥ 400` → `D ≤ 2.5 × (P_eff − A_cur)` | 所有情形 |

`A_cur` / `P_cur` clamp 到 `[0, A_max]` / `[0, P_max]`，负值按 0 处理（v1.1 旧值「clamp 到 `[0,999]`」作废：那是旧的点数尺度）。升级池不含物抗，故档位只来自数据表。

### 2.6 三种 `res_mode` 数值对照（**v1.2 重算并保留**；C2 后默认改为 MULTIPLY）

> 这张表的价值就是**展示三种读法的差异**，所以在 v1.2 里重算后保留，只把「默认」标注从 DIVIDE 改到 MULTIPLY。v1.1 的旧表（R = 0/10/20/30/40/60/90% 连续行）已作废。

| `res_mode` | 公式 | 物抗的语义 | 有界性 | v1.2 定位 |
|---|---|---|---|---|
| **`MULTIPLY`** | `D = (P−A) × (1−R)` | **物理真减伤**（R 越高挨打越轻） | 天然有界：`D ≤ P−A`；免疫档 `D≡0` | **默认**（C2 用户算例） |
| `DIVIDE` | `D = (P−A) / (1−R)` | **物理易伤**（R 越高挨打越痛） | `R→1` 发散，靠 600‰ 上限截断；`R=1000` 除零 | 备选配置项（不再默认） |
| `FLAT` | `D = (P−A) − R×P` | **物理免疫开关**（R 高直接免伤） | 有界，但极易归零 | 备选配置项（不再默认） |

同一算例、三种模式（P=12、A=8、平地、无精力、严格模式）：

| 档位（R） | DIVIDE `(P−A)/(1−R)` | MULTIPLY `(P−A)×(1−R)` ★默认 | FLAT `(P−A)−R×P` |
|---|---|---|---|
| 无 0 | 4.000 → 4 | 4.000 → 4 | 4.000 → 4 |
| 低 0.2 | 5.000 → 5 | 3.200 → 3 | 1.600 → 1 |
| 中 0.4 | 6.667 → 6 | 2.400 → 2 | −0.800 → **无法造伤** |
| 高 0.8 | **20.000 → 20** | 0.800 → **80% 造 1** | −5.600 → **无法造伤** |
| 免疫 1.0 | **除零 → 非法（备选模式下必须拒绝）** | **0 → 恒无法造伤**（C5） | −8.000 → **无法造伤** |
| ~~0.6（v1.1 旧上限）~~ | ~~10.000 → 10~~ | 1.600 → 1 | −3.200 → 无法造伤 |

**v1.2 重算**。三条要点：

- **`DIVIDE` 在免疫档下是除零**，不是「伤害 40」：备选模式必须把免疫档判为非法数据（§2.5 L2）。「高」档在 DIVIDE 下是 **20 点核弹**（差值 4 × 5）——这就是 DIVIDE 不该当默认的直接理由。
- **`FLAT` 与五档不兼容**：`FLAT` 要至少造 1 点需 `(P−A) − R×P ≥ 1`，即 `R ≤ (P−A−1)/P`。以 P=12/A=8 为例 → `R ≤ 250‰`，只有 **无 / 低** 两档可用；中/高/免疫一律「无法造伤」。选 `FLAT` 就必须重做全部原型档位（§9.5）。
- **`MULTIPLY` 让五档成为干净的身份标签**：伤害恒为 `差值 × {1.0, 0.8, 0.6, 0.2, 0}`，所以「无 → 高」正好是 **5 倍耐久**的跳跃（§1.1 档位表），而「差值」仍是经典的力量/护甲博弈。

| 8 | 掷弹手 → 石肤守卫 | 高 0.8 | 1 | 0.2 | **20%** |

> **v1.2 重算**（v1.1 的「平地 0/64」与「16/128、命中率 25%~88%」两张旧表**均已被取代**）。结构上这 8 组全部是「**以弱打强 / 以强打肉**」：4 组打高抗的石肤守卫、2 组打塔盾卫、2 组是低抗但护甲逼近的剑士。这正是概率判定应该出现的位置，因此 **C3 成立：该分支不再是死代码，也不再需要高低差来救它**。

**（3）可选高低差（降级为风味机制，默认关闭）**：若打开 `HEIGHT_POWER_MOD=100`（攻方高于目标 ×1.1、低于 ×0.9），128 组高/低地对局中 **16 组**落进概率区间，命中率 **8%~96%**（比平地多 8 组）。它现在只提供**地形风味与额外张力**，不再是机制存活的必要条件；v1.1 旧表述「平地该分支不出现、必须靠高低差触达」**已被 v1.2 取代**。

**（4）概率判定的占比监控**：`balance_sim` 必须输出「落入 `0<D<1` 的攻击次数 / 总攻击次数」。v1.2 的设计预期是 **10%~25%**（平地 12% 是下限，实战里精力投入与护甲被打低都会降低占比）。低于 5% 说明数值表被调得过于「整齐」，高于 40% 说明大量攻击只能靠 1 点伤害推进、战斗会拖长。

**（5）方案 B（可选增强开关，默认关闭；v1.2 下价值上升）**：v1.2 的 `D ≥ 1` 也常带小数（3.2 / 2.4 / 4.8 …），严格模式的 `floor` 会**丢弃最多 44% 的伤害**（§2.9）。方案 B 把小数兑现：`base = floor(D_milli/1000)`；仅当 `base ≥ 1` 且 `frac > 0` 时掷 1~1000，`≤ frac` 则 `damage = base + 1`；`base = 0` 时严格规则已与 B 数学等价（`ceil(D_milli/10)/100` 概率造 1 点），**不重复掷骰**。事件层始终区分 miss / damage（`branch`：`AUTO` / `HIT_OR_MISS` / `NO_DAMAGE` / `AUTO_PLUS` / `ARMOR_PIERCE`），因为玩家需要看到「是没打中，不是打不动」。

| 算例 D | 严格模式：伤害 | 方案 B：保底 + 概率 | 两模式 E[D] |
|---|---|---|---|
| 0.65 | 0 / 65% 造 1 | 0 + 650‰ | 0.65 / 0.650 |
| 2.50 | 2 / 必中 | 2 + 500‰ | 2.50 / 2.50 |
| 3.20（民兵→民兵，低抗） | 3 / 必中 | 3 + 200‰ | 3.20 / 3.20 |
| 4.80（重弩手→剑士，低抗） | 4 / 必中 | 4 + 800‰ | 4.80 / 4.80 |
| 8.00（剑士→弓手，无抗） | 8 / 必中 | 8（frac=0，不掷骰） | 8.00 / 8.00 |
| 0.20（掷弹手→石肤守卫，高抗） | 0 / 20% 造 1 | 0 + 200‰ | 0.20 / 0.200 |
| 1.00 / 7.00 | 1 / 7，必中 | 1 / 7（frac=0，不掷骰） | 1.00 / 7.00 |

> **v1.2 默认 = 严格字面规则 + 高低差关闭**：`D ≥ 1` 必中且只给 `floor(D)`；`0<D<1` 按 `ceil(D_milli/10)%` 掷骰。方案 B 与高低差**互不冲突**、可独立或同时开启；开启方案 B 后 E[D] 恰等于 D，§2.9 的取整损耗全部归零。
> **v1.1 旧内容已被取代**：旧「方案 A 提高属性粒度（护甲 = 力量 × 0.55~1.10，允许 156/157/158）」作废 —— 五档离散抗性已经把概率区间自然打开，不再需要 3 位有效数字的属性粒度；旧「方案 C 靠势均力敌设计」同理作废。

### 2.8 `0<D<1` 分支的命中率取整：`ceil`（默认）vs `round_half_up`（备选）

| D_milli | 1 | 5 | 11 | 15 | 114 | 115 | 650 | 800 | 999 |
|---|---|---|---|---|---|---|---|---|---|
| D | 0.001 | 0.005 | 0.011 | 0.015 | 0.114 | 0.115 | 0.650 | **0.800** | 0.999 |
| `ceil`（默认） | 1% | **1%** | 2% | 2% | 12% | 12% | **65%** | **80%** | 99% |
| `round_half_up` | 1% | **1%** | 1% | 2% | 11% | 12% | **65%** | **80%** | 99% |

两者在用户给的两个例子上一致（0.65→65%、0.005→1%）；差异出现在千分比末位 1~4 的取值上（约占四成）。`ceil` 永不低估伤害，故为默认。

> **v1.2 补充**：五档让 `D_milli` 大量取整齐值（200/400/600/800 的倍数），其中 **800‰ → 80%** 是最常见的高抗格（§2.7 表里出现 3 次），此时 `ceil` 与 `round_half_up` 一致；取整分歧只在**脏档位钳制、精力投入或高低差修正产生的非整齐值**上出现，所以 `HIT_ROLL_ROUND` 的切换影响面比 v1.1 小。

### 2.9 严格模式的取整损耗（**v1.2 新增**；这是 C2 乘算的隐藏代价）

`D ≥ 1` 时伤害取 `floor(D)`，小数部分被丢弃。五档让 D 大量落在「整档位倍数 × 小数」上，所以损耗不可忽略：

|---|---|---|---|
| 1 | 0.8 / 0.80 / 0% | 0.6 / 0.60 / 0% | 0.2 / 0.20 / 0% |
| 2 | 1.6 / 1.00 / **38%** | 1.2 / 1.00 / 17% | 0.4 / 0.40 / 0% |
| 3 | 2.4 / 2.00 / 17% | 1.8 / 1.00 / **44%** | 0.6 / 0.60 / 0% |
| 4 | 3.2 / 3.00 / 6% | 2.4 / 2.00 / 17% | 0.8 / 0.80 / 0% |
| 5 | 4.0 / 4.00 / 0% | 3.0 / 3.00 / 0% | 1.0 / 1.00 / 0% |
| 6 | 4.8 / 4.00 / 17% | 3.6 / 3.00 / 17% | 1.2 / 1.00 / 17% |
| 8 | 6.4 / 6.00 / 6% | 4.8 / 4.00 / 17% | 1.6 / 1.00 / **38%** |
| 10 | 8.0 / 8.00 / 0% | 6.0 / 6.00 / 0% | 2.0 / 2.00 / 0% |

> **v1.2 重算**（「期望」= 严格模式下单次攻击的期望伤害：`D ≥ 1` 取 `floor(D)`；`0 < D < 1` 取 `ceil(D_milli/10)/100`）。

## 4. 回合与行动结构

### 4.1 行动经济

| 项 | 规则 |
|---|---|
| 每单位每回合 | **1 次移动**（≤ MP 格）+ **1 次主动行动**（攻击 / 技能 / 休息），二者**独立、顺序任意** |
| 攻击后能否移动 / 移动后能否攻击 | 都能（各自额度独立） |
| 放弃 | 移动与主动行动都可放弃；主动行动固定 1 次，不可拆分、不可重复 |
| 移动力累积 | 不累积，回合开始重置为 MP |
| 反击 | v1 **无反击**（`RIPOSTE=false`） |
| 范围校验时点 | 行动开始时校验一次，行动开始后不再变化 |

决策：**移动为独立行动**（`MOVE_IS_SEPARATE=true`）。理由：口述规则完全没提移动；若与攻击绑定，近战在 12×12 棋盘上会长期「要么赶路要么挨打」，单场被拖到 8 回合以上，违反 3-6 回合目标。备选：二选一（更硬核），此时 TTK 不变但回合数 +2~+3。

### 4.2 精力规则

| 问题 | v1 判定 |
|---|---|
| 是什么 | 战局内资源池；进入战局时 `EP = EPmax`；**稀缺的「补差值」资源**（v1.2：不再是「每战 1 次必杀」，见下方定位修正） |
| 每回合上限 / 谁可消耗 | **最多消耗 3 点**，额度在该单位自己的回合开始时重置；仅攻击或技能可消耗，**休息不消耗** |
| 加成值 | 1 点 = +2 伤害（**占位起点，C8**：角色力量尺度未定，后续按比例放大） |
| 力量攻击 | `P_eff = (P_cur + 2n) × 高低差系数`（高低差默认关） → **加在差值上**，实际倍率 = `(差值 + 2n) / 差值`：差值越小越暴利（差值 1 时 ×7.0，差值 6 时 ×2.0，§3.3） |
| 破甲攻击 | `伤害 = BD + 2n`，直接加在最终伤害上，不被物抗档位缩放、不受高低差影响（恒 ×2.0） |
| 双上限 / 分配 | 受「剩余 EP」与「本回合剩余额度(3−已用)」双重限制；一次攻击内一次性声明投入 n 点，不可撤回 |
| 回复 / 死亡 | 只有休息 +1（不超过 EPmax），且休息会放弃当回合普攻；阵亡单位 EP 清零 |
| 可选抑制 | `ENERGY_TURN1_LOCK=true` 禁止第 1 回合投入精力（防「开局倾泻精力秒核心」） |

决策：精力是「战局资源 + 每回合额度」双重限制。决策：精力对破甲**直加**、对力量**加进力量（即加进差值）**（原文「对力量时加进己方力量里」）——这一条与用户原话一致，因此**不改**；抑制手段为 `EPmax ≤ 4` + 每回合只回 1 点 + §10.5 占比监控（备选 `ENERGY_BD=1`，与原文冲突故不默认）。

> **v1.2 定位修正（C8）**：v1.1 把 3 点精力称为「稀缺爆发资源 / 每战 1 次满爆发」，但重算后 **3 点精力在严格模式下只有 16% 的对局能一击清空力量池**（v1.1 旧值是 75%，§10.4），精力不再是秒杀手段，而是**「补差值」的稀缺资源**：差值越小收益越大，因此它的正确用法是「把打不动的目标推进概率命中区间」或「补最后 2~3 点」。所有精力数值（`ENERGY_POWER_MILLI=2000`、`ENERGY_BD=2`、每回合 3 点、`EPmax 2~4`）都是**占位起点**，角色力量尺度确定后按比例放大，并用 §10.5 的占比监控重标定。

### 4.3 休息

| 项 | 判定 |
|---|---|
| 是什么 | 一种主动行动（仍需未使用本回合主动行动） |
| 恢复 | `P_cur = min(P_max, P_cur+RS_P)`；`A_cur = min(A_max, A_cur+RS_A)`；`EP = min(EPmax, EP+1)` |
| 结算顺序 | 力量 → 护甲 → 精力（互不影响，固定顺序仅为可测试性） |
| 可被攻击 / 移动后休息 | 可以，休息**没有防御加成**；允许移动后休息 |
| 上限 | P_max / A_max 为**当前上限**（含升级加成） |

### 4.4 行动顺序与阶段机

```
回合开始(先手方) → 该方单位按玩家自选顺序逐个：[移动阶段] → [主动行动阶段] → [死亡判定]
                 → 先手方完毕 → 后手方重复（AI 按原型优先级） → 回合结束，回合数+1
```

同一方内部**无固定行动顺序**。AI 固定顺序：远程 → 弹道 → 近战 → 肉盾；同类型按「能击杀者优先，其次剩余池最低」。回合制采用 **IGOUGO + 玩家方先手**（`TURN_MODE="igougo"`）；备选 `alternating`（我方1→敌方1→…）用于削弱先手优势（§10.6 R-1）。

## 5. 移动与地形

### 5.1 移动

| 项 | 判定 |
|---|---|
| 邻接 | **4 邻格（正交）**，对角不可（与近战共用同一函数） |
| 每格消耗 | 平地 1 MP；**上坡每阶额外 +1 MP**；下坡 +0 |
| 高度差 | 相邻格 `∣Δh∣ ≥ 2` 视为断崖，**不可直接移动**（需绕路） |
| 占位 | 1 格最多 1 个存活单位；不可穿越、不可停止 |
| 寻路 | 4 邻 BFS，路径总消耗 ≤ MP；无合法路径则不可移动到该格 |
| 阵亡 / 触发 | 阵亡单位立即移除、**不留尸体阻挡**；无借机攻击 |
| 高度 | `h ∈ {0,1,2}`，仅高度，无其他地形类型 |

### 5.2 高低差的四个作用点

| 作用点 | 规则 |
|---|---|
| 移动 | 上坡每阶 +1 MP；`∣Δh∣ ≥ 2` 不可直接通行 |
| 近战邻接 | 相邻且 `∣Δh∣ ≤ 1` 才可近战 |
| 远程 | 曼哈顿距离 ≤ RNG 且 `∣Δh∣ ≤ 2`，无遮挡概念 |
| 力量修正 | **可选（默认关闭，C3）**：开时攻方高于目标 ×110%、低于 ×90%、相同 ×100%（千分比，四舍五入，`HEIGHT_POWER_MOD=100`） |
| 破甲 / 弹道 | 破甲**不受高低差影响**；弹道只做落点距离的单次高度修正（§6.2），判定范围忽略高度 |

决策：高低差 ±10% 力量修正现在是**可选风味机制**，`HEIGHT_POWER_MOD` **默认 0（关闭）**。理由：(a) v1.2 的五档离散抗性已经让 `0<D<1` 成为常态（平地 8/64，§2.7），**不再需要用高低差去救概率分支**（v1.1 的这条理由已作废，见 §13 D16）；(b) 关闭后地形仍有三个作用点（上坡 +1 MP、断崖不可通行、近战/远程高度限制），地形价值不依赖这条修正；(c) 打开后 128 组里落进概率区间的对数从 8 增到 16、命中率 8%~96%，可作为「地形更锋利」的配置档。

## 6. 三种普通攻击

### 6.1 总览

| 攻击方式 | 目标选择 | 命中 | 伤害 | 可否打护甲 | 关键属性 |
|---|---|---|---|---|---|
| 近战 | 相邻 4 格内 1 个敌人，`∣Δh∣ ≤ 1` | 必中（保底伤害不落空） | §2 公式 | 可 | 无 |
| 弹道 | 玩家输入方向+力度，**落地菱形范围内全部敌人** | 落点判定（确定性） | §2 公式，每目标独立结算 | 可 | 判定半径 SPL |
| 远程 | 曼哈顿距离 ≤ RNG 的 1 个敌人，`∣Δh∣ ≤ 2` | 无瞄准/闪避判定 | §2 公式 | 可 | 射程 RNG |

- 决策：**远程「必命中」= 不存在独立命中率/闪避判定**，伤害公式照常结算。备选 `RANGED_MIN_1=true`（远程 D<1 直接造 1）。
- 决策：**弹道没有独立命中率属性**。「命中」= 落点菱形内存在该目标（技术决定），「造伤」= 公式结算。
- 决策：判定范围 = **以落点格为中心的曼哈顿距离 ≤ SPL 的菱形**（SPL=1 → 落点 + 4 邻格，共 5 格）；备选 `SPLASH_SHAPE="chebyshev"`（3×3）。
- 决策：菱形内**所有敌方单位各自独立结算**（AOE），顺序 = 到落点曼哈顿距离升序，同距按 (y, x) 升序；备选 `SPLASH_HITS_ALL=false`。
- 决策：**无友军伤害**（`FRIENDLY_FIRE=false`），理由是无辅助瞄准 UI，误伤会造成不可控挫败。

### 6.2 弹道瞄准输入映射（可直接实现）

| 输入 | 取值 | 量化 | 操作方式 |
|---|---|---|---|
| 方向 θ | 0° ~ 355° | **步进 5°**（72 档） | 鼠标相对施法者的方向量化到 5°；或方向键微调 |
| 力度 p | 0 ~ 100 | **步进 10**（11 档） | 按住蓄力 0.6 秒线性满格后松开并量化；或数字键 |

角度定义：以 **+x 轴为 0°，向 +y（屏幕下方）为正，顺时针**。UI 只显示「角度数值 + 力度百分比」，**不显示预测落点、不显示抛物线预览**（符合「无辅助瞄准 UI」）。

```
v0 = 2.0 + p/10                       # 格/回合：p=0 → 2.0，p=100 → 12.0
g  = 16.0                             # 格/回合²，固定
Range_flat = v0^2 * sin(2θ) / g       # 平地射程（格）
Range = Range_flat - 1.5 * (h_land - h_caster)   # 高度单次修正：用无修正落点取 h_land，只迭代一次
落点连续坐标 = (x+0.5, y+0.5) + Range * (cosθ, sinθ)
落点格 = (floor(px), floor(py))       # 恰为整数按 floor；越界 → 落空
```

最大射程：p=100、θ=45° → **9.0 格**。决策：落点越界 → **落空，无事发生**，仍消耗行动与已投入精力。决策：飞行途中**不可被阻挡**（无美术资源、无碰撞体）；备选 `PROJECTILE_BLOCKABLE=true` 需额外定义命中阻挡物的结算。

## 7. 战斗流程、胜负与结算

| 项 | 判定 |
|---|---|
| 初始化 | 读入部署；`P_cur=P_max`、`A_cur=A_max`、`EP=EPmax`；回合数=1；PRNG 状态取自存档 |
| 玩家阶段 / 敌方阶段 | 玩家自由顺序操作己方单位（每个最多 1 移动 + 1 主动行动）/ AI 按 §4.4 顺序操作 |
| 回合结束 | 清理回合标记；回合数+1；检查胜负 |
| 胜利 | 一方全部阵亡（**力量池归零**，护甲池归零不减员） |
| 超时 | 回合数 > 30 → 存活单位数多者胜 → 相同则 `Σ(P_cur+A_cur)` 大者胜 → 仍相同判平局 |
| 阵亡处理 | 立即移出棋盘；未执行的行动作废；已投入精力不返还；本场击杀进度写入存档 |
| 战后顺序 | ① 存活单位回满池与精力 ② 结算击杀与升级 ③ 玩家分配属性点 ④ 写存档 |
| AI 硬要求 | 任何情况下都必须给出「移动 + 一个动作」，**绝不站桩**；效用函数含 `−0.35 × 到最近敌人的曼哈顿距离`，远程另加 `−1.6 × (距离−1)`（附录 A6 实算：站桩 AI 胜率 0%） |

## 8. 升级与成长

### 8.1 人头阈值

| 等级 | 升到下一级所需**新增**击杀 | 累计击杀（等价） |
|---|---|---|
| L1 → L2 | 1 | 1 |
| L2 → L3 | 2 | 3 |
| L3 → L4 | 4 | 7 |
| L4 → L5 | 8 | 15 |
| L5 | 满级，不再成长 | — |

决策：**每级清零**（`LEVEL_RESET_PER_LEVEL=true`），语义为「升级所需人头分别为 1/2/4/8」。备选 `LEVEL_THRESHOLD_MODE="cumulative"`：把 1/2/4/8 当作绝对累计阈值（L2@1、L3@2、L4@4、L5@8）。每级清零需 **15 杀**满级，累计阈值只需 **8 杀**。因战棋是 RPG 的子模块，击杀计数在**整个战役中累计并写入存档**；附录 A7 的 6v6 模拟显示 5-6 人小队单场可稳定到 3 级（1/2/4），5 级必须靠跨战斗累计 —— 这确认了「跨战斗累计」是必要的（Q4）。单次击杀最多升 1 级。

### 8.2 属性点

| 项 | 判定 |
|---|---|
| 每级获得 / 可选池 | 3 点；力量、护甲、精力上限、破甲伤害、休息恢复力量、休息恢复护甲 |
| 远程额外 / 弹道额外 | 射程（+1 格/点） / 落地命中判定范围（+1 半径/点） |
| 兑换率 / 重复投入 | 1 点 = 对应属性 +1；允许同一属性连续加 |
| 不可加 | **物抗、魔抗**（C1：五档**固有**能力，玩家永远无法改变；原文升级池里也没有它们）；破甲/魔抗的档位只能来自数据表 |
| 上限（**v1.2 占位尺度上调，C8 / §13 D31**） | 力量 **30**、护甲 **24**、精力上限 **4**、破甲 **18**、休息恢复 8、射程 10、判定半径 3 |
| 未分配点 / 升级时点 | 保留可跨战斗累积；**战斗结束后统一结算**（`LEVEL_UP_MODE="post_battle"`） |
| 玩家 / AI 分配 | 战后界面手动分配 / 按原型预设方案自动分配（§8.3），循环取用 |

> **v1.2 上限调整的理由与遗留冲突（重要）**：占位尺度上调到 P 9~14 / A 5~11 后，v1.1 的旧上限（P 20 / A 15 / BD 12）只够 2 级成长（每级 3 点、满 5 级共 12 点）—— **满级角色的 12 点无法全部投入同一属性**。因此按「建卡上限 + 12 ≤ 上限」重设：P 15+12 → **30**、A 12+12 → **24**、BD 6+12 → **18**。精力上限刻意保持 **4**（K3 的 `EPmax ≤ 4` 是设计约束，§10.4），代价是 `EPmax=4` 的原型无法再投入精力上限，只有 `EPmax=2~3` 的原型能获益（+1~+2），这是**有意的取舍**。
> **仍存在的冲突（已上报，§13 Q10）**：物抗档位是 ×1.25 / ×1.67 / ×5 的**乘法**跳跃，而升级只给 +3 点**加法**成长（同尺度下约 ×1.2~×1.5 耐久）→ 一个「高」档单位无论等级多低都远硬于「低」档满级单位。**v1 的处置是把它当身份标签、不当成长曲线**（§9.4 MR1）；若以后要给玩家「越练越硬」的成长感，只能走护甲线，不能走档位线。

决策：升级**战斗结束后**统一结算。理由：(a) 战斗中弹 UI 打断节奏；(b) 单场 3-6 回合内每单位通常只有 0-2 杀，即时升级几乎不触发；(c) 保证 §10 的 TTK 推演成立。备选 `LEVEL_UP_MODE="immediate"`。

### 9.4 MULTIPLY（v1.2 默认）下「物抗」的设计逻辑：**真减伤**（整节重写，取代 v1.1 的「物抗=易伤」DR1~DR5）

**核心事实**：`(1−R)` 是一个**独立乘数**，只压缩伤害、不改变「差值」的语义。于是 `TTK = [1/(1−R)] × [P/(P−A)]` 把两个旋钮彻底解耦：

| 旋钮 | 影响 | 取值粒度 |
|---|---|---|
| 物抗档位 | **整体耐久倍率**：×1.00 / ×1.25 / ×1.67 / **×5.00** / ∞ | 五档离散（不可加点） |
| 护甲/力量比 | **差值旋钮**：同时决定伤害值与「是否落进概率命中区间」 | 连续（每级 +1 点） |

以「剑士（P=14）打护甲 8 的目标」为基准，只改目标档位：

| 目标档位 | 实际伤害 | 等效耐久 | 定位 |
|---|---|---|---|
| 无 0 | 6.00 | ×1.00 | 基准 / 脆皮 |
| 低 0.2 | 4.80 | ×1.25 | 标准职业兵 |
| 中 0.4 | 3.60 | ×1.67 | 坦克档 |
| 高 0.8 | 1.20 | **×5.00** | 精英 / Boss 候选（C9 警示） |
| 免疫 1.0 | 0 | ∞ | v1 不可击杀（C5） |

**构造规则（v1.2 取代 v1.1 的 DR1~DR5）**：

| 编号 | 规则 | 理由 |
|---|---|---|
| MR1 | **档位表达身份，不表达成长**：无=炮灰/标准、低=职业兵、中=坦克、高=精英/Boss、免疫=Boss 机制 | 档位是 ×5 级别的跳跃，而升级只有 +3 点（§8.2 冲突说明） |
| MR2 | **高抗单位必须压护甲或压力量池**（石肤守卫 A=9、P=12 是反面教材） | 高护甲与高抗是**独立相乘**的两个耐久旋钮，叠乘会把 TTK 推到 7~15 回合（§9.2 C9） |
| MR3 | **中抗是「坦克档」的最佳落点**：×1.67 近似于把 A/P 从 0.67 压到 0.2 的效果，但不会让力量线完全失效 | 塔盾卫（中抗 + A=11）用数值冗余换来了「力量线彻底打不动」，属刻意设计 |
| MR4 | **不要做「无抗 + 高护甲」的纯肉盾** | 没有档位乘数时唯一耐久来源是护甲，而 `护甲 ≥ 力量` 会把战斗直接推向破甲线（C1 提示），且差值 ≥1 就必中 → 概率命中分支消失 |
| MR5 | **物抗不进升级池，且必须与「力量线打不动」的意图一致**：档位越高，玩家越应被推向破甲线或（v2）魔法 | C1 + C5：免疫档必须配魔法技能 |
| MR6 | **敌我双方都要有「可打」的目标**：每方至少 1 个无/低抗单位，否则双方都在打坦克，节奏必然拖长 | v1.2 实算：石肤守卫把 TTK 涨到 7~15 回合（§9.2 C9） |

**对石肤守卫（高 0.8、A=9、力量池 12）的三条攻击线实算**：力量线（无精力）剑士 1.00、破甲者 1.20、民兵 0、塔盾卫 0；力量线（+3 精力）剑士 2.20；破甲线 `BD+2n`：破甲者 6.0/8.0/10.0/12.0、掷弹手 4.0/6.0/8.0/10.0 —— **破甲是标准解法（破甲者 2 回合打空 A=9），力量是终结手段**。这就是「每回合选择攻击力量还是护甲」的咬合点，而且 v1.2 下**不再需要任何数值护栏**（v1.1 的 DIVIDE 才需要 `R ≤ 600‰`）。

### 9.5 切换到 `DIVIDE` / `FLAT`（备选）后的重调流程

> v1.2 默认是 `MULTIPLY`；本节只在「用户改主意要回到原文除法读法」或「试验 FLAT」时使用。**`DIVIDE` 会反转物抗语义（物抗=易伤），必须整体重调数值表，不能只改一个枚举。**

| 步骤 | 动作 |
|---|---|
| 1 | 切换 `res_mode`；`DIVIDE` 下同时启用 §2.5 的 L1~L4 护栏（`R ≤ 600`、免疫档判非法） |
| 2 | **重做档位映射**：`DIVIDE` 必须把档位重映射到低值（例如「高」也只能取 0.2），否则 0.8 档在差值 4 时给出 20 点核弹；`FLAT` 只有 无/低 两档可用（判据 `R ≤ (P−A−1)/P`，§2.6） |
| 3 | 跑 §13.3 的自动对战 100 局，检查「胜率 40%~60%」「平均回合 3.0~6.0」 |
| 4 | 只调档位与护甲，**重算 §10 全部矩阵**，验收仍是「1v1 TTK 2~4 回合、集火 1 回合」；`FLAT` 下还需复核 §2.9 的取整损耗（该模式极易归零） |
| 5 | 同步更新 §13.3 验收向量与 `data_schema.md` 的档位字段（若档位集合变化） |

**为什么 v1.2 不建议切回去**：`DIVIDE` 让「物抗」名实相反（越高越挨打），且免疫档在它下面直接除零；`FLAT` 与五档枚举不兼容（只有两档可用）。两者唯一的价值是**对照实验**（§2.6 那张表就是为此保留的）。

> 3. **塔盾卫列**（A=11）对民兵/塔盾卫/掷弹手是 **0**：这正是 §9.2 C1 的「死锁」格，也是 C6 提示级警示要覆盖的对象。

### 10.4 「一击清空检查表」（**v1.2 重算**）

口径：8 原型 × 8 原型 = 64 组对局；力量线取**该次攻击的最大可能伤害**（严格模式 = `D ≥ 1` 时 `floor(D)`、`0<D<1` 时按命中取 1；方案 B = `floor(D)+1`）；破甲线取 `BD + 2n`。**注意 C5/C7**：清空力量池 = 击杀；清空护甲池 = 只是剥防御，**不击杀**。

| 精力 n | 一击清空**力量池**（= 击杀）：严格 / 方案B | 一击清空**护甲池**（= 剥防御） |
|---|---|---|
| 0 | **0/64（0%）** / 0/64（0%） | 5/64（8%） |
| 1 | **0/64（0%）** / 2/64（3%） | 12/64（19%） |
| 2 | 3/64（5%） / 5/64（8%） | 43/64（67%） |
| 3 | 10/64（16%） / 13/64（20%） | 52/64（81%） |

**断言与定性（v1.2 重写）**：

- K1（硬）：`n=0` 一击清空力量池 ≤ **10%** —— 严格模式 **0%**、方案 B **0%** ✓。无精力时不存在「白嫖秒杀」。
- K2（硬）：`n=1` ≤ **25%** —— 严格模式 **0%**、方案 B 3% ✓✓（v1.1 旧值 12%/22%，v1.2 下精力远不够看）。
- K3（设计约定，**v1.2 语义反转**）：v1.1 写「`n=3` 允许一击带走脆皮（75%）」；v1.2 实测只有 **16%**（方案 B 20%），因为力量池（9~14）相对 +6 精力变大了。因此 K3 改为：**`n=3` 的定位不是秒杀，而是「补差值 / 推进概率区间」**（差值 1 时伤害 ×7.0，§3.3），约束不变：① `EPmax ≤ 4` 且每回合上限 3 → 每单位每战最多 **1 次**满爆发；② 休息回能要放弃当回合普攻；③ 可用 `ENERGY_TURN1_LOCK=true` 禁止第 1 回合爆发。**若以后希望恢复「爆发=击杀」的手感，正确做法是按 C8 放大角色力量尺度时同步放大 `ENERGY_POWER_MILLI`，而不是改这条断言。**
- K4：护甲池的一击清空**不是击杀**（§3.3 B5/B6 已验证），它是「开罐」；`n=3` 时 81% 可开罐，符合破甲者/掷弹手的存在意义。
- ⚠️ **v1.1 的旧结论全部作废**：旧表 `n=3` 严格 48/64（75%）、`n=1` 8/64（12%）、`n=0` 5/64 护甲清空（3%）等数字都基于旧数值表与 DIVIDE，**不可再引用**（v1.2 对应值为 10/64、0/64、5/64）。

### 10.5 精力占伤害比（监控项；**v1.2 重算**，目标 20%~35%）

口径：一场 3 次攻击的战斗（2 次无精力 + 1 次投入 3 点精力），目标为剑士（A=8、低抗 0.2）。

| 原型 | EPmax | 无精力 E[D] | 爆发 E[D] | 3 次总伤害 | 精力占比 | `ENERGY_POWER_MILLI=1500`（+4.5/点） | `EPmax=2` |
|---|---|---|---|---|---|---|---|
| 剑士 / 重弩手 | 3 | 4.80 | 9.60 | 19.20 | **25%** | 20% | 18% |
| 弓手 | 3 | 4.00 | 8.80 | 16.80 | **29%** | 23% | 21% |
| 破甲者 / 石肤守卫 | 4 | 3.20 | 8.00 | 14.40 | **33%** | 27% | 25% |
| 掷弹手 | 4 | 1.60 | 6.40 | 9.60 | **50%** | 43% | 40% |
| 民兵 / 塔盾卫 | 3 | 0.80 | 5.60 | 7.20 | **67%** | 60% | 57% |

> **v1.2 重算**（v1.1 旧表 40%~67% 基于旧数值与 DIVIDE，已作废）。实测区间 **25%~67%**，仍高于 20%~35% 目标，但结构变了：
> 1. **主力兵种（剑士/重弩手/弓手）已经落在 25%~29%**，基本达标 —— 因为 v1.2 的伤害基数变大了（力量池 9~14、伤害 3~8），+6 力量的相对权重下降。
> 2. **偏高的只有「差值极小」的退化格**：民兵/塔盾卫打剑士（差值 1）占 67%、掷弹手打石肤守卫（差值 1）占 50%，因为它们的无精力伤害本来只有 0.2~0.8，任何加成都显得巨大。**这两类格恰恰是精力最该用的地方**（把 20% 概率推到 80%），所以不应按它们调低 `ENERGY_POWER_MILLI`。
> 3. `balance_sim` 必须把「精力伤害 / 总伤害」作为一等监控指标，**> 45% 即判定爆发过强**；杠杆顺序：先 `ENERGY_POWER_MILLI=1500`（把主力压到 20%~27%），仍超标才 `EPmax=2`。v1.2 默认仍按原文 `ENERGY_POWER_MILLI=2000`（占位起点，C8）。

### 10.6 节奏推演与风险（**v1.2 重算**）

不变式：
- **I1** 常规 1v1 混合线 TTK = **1.3~5.5 回合**（严格模式，§10.2 ③），其中主力对局（无/低/中抗目标）落在 **2~4 回合**，符合 C2 的 2.5~3.5 目标；
- **I2** 集火（3~4 单位）把单个目标的 TTK 压到 **1 回合**（4 单位齐射对无抗目标可达 8+6+7+... ≫ 力量池）；
- **I3** **3 点精力不再是「必杀」**（v1.2：`n=3` 一击清空力量池仅 **16%**，§10.4），它的作用是「把概率命中推到必中 / 压缩 1 回合」，每战仍最多 1 次满爆发；
- **I4** 全场 8 单位 → 每回合可行动单位数 8、8、6、4、2（**前提是不含高抗单位**；含石肤守卫时后段会拖到 7 回合以上，§9.2 C9）。

| 回合 | 开始存活 | 可行动 | 本轮阵亡 | 说明 |
|---|---|---|---|---|
| 1 | 8 | 8（能开火 3） | 0~1 | 近战移动 4 格仍差 2 格，只有远程/弹道开火 |
| 2 | 7~8 | 7~8 | 1 | 全员接战；破甲开罐 + 集火；概率命中开始频繁出现 |
| 3 | 6 | 6 | 1 | 精力通常用在此回合（补差值，而非秒杀） |
| 4 | 4 | 4 | 1~2 | 劣势方崩盘 |
| 5~6 | 2 → 0 | 2 → 0 | 1~2 | 收尾；最慢路线（不集火、不用精力）在第 6 回合结束 |

**单场 3-6 回合**：快线 = 开罐 + 集火 → 3-4 回合；慢线 = 各自为战 / 大量概率格 → 6 回合。**每回合 4-8 单位**：回合 1-4 为 8/8/6/4 ✓；第 5 回合的 2 个属收尾。**唯一的系统性偏离来源是 `高` 档单位**（C9）：一个 ×5 耐久的单位会把战局从 4 回合推到 8~15 回合，因此 v1 普通关卡需要限制高抗单位的数量与配套数值。

| 风险 | 实算依据 | v1.2 处置 |
|---|---|---|
| R-1 先手碾压 | 附录 A7：镜像 6v6、TTK 1.8~2.0 时先手方胜率 **100%** | v1.2 TTK 拉到 1.3~5.5（主力 2~4）；验收线仍是「先手胜率 ≤ 70%」，超标切 `TURN_MODE="alternating"` |
| R-2 精力收益失衡 | §10.4（`n=3` 击杀率 16%）、§10.5（占比 25%~67%） | `EPmax ≤ 4`、每回合只回 1 点、占比 45% 红线、`ENERGY_TURN1_LOCK` 可选。**v1.2 的侧重点从「爆发过强」改为「差值 1 的格子上精力收益 ×7.0 过高」** —— 靠 AI 评分与 `ENERGY_TURN1_LOCK` 抑制开局投入 |

```
state = (state * 1103515245 + 12345) mod 2^31
roll_1_to_100  = ((state >> 16) mod 100)  + 1     # 严格模式：0<D<1 的概率命中
roll_1_to_1000 = ((state >> 16) mod 1000) + 1     # 方案 B（可选）：小数额外 +1
```

消耗掷骰的两种情形：① 严格模式下 `0 < D_milli < 1000` 的概率命中（**v1.2 下频繁发生：平地 8/64 配对，§2.7**）；② 方案 B 开启且 `base ≥ 1` 且 `frac > 0` 时的小数额外 +1。破甲线、免疫档（`D≡0`）与「`P ≤ A` 无法造伤」**不消耗**掷骰。同 seed 两次运行产生完全相同的战斗过程（可回放、可做确定性测试）。

### 13.3 验收测试清单（**v1.2 重写**，可直接写成自动化用例）

1. §3.1 全部 **22 组**算例逐条断言（`D`、严格伤害、命中率、方案 B 期望），含 A19 免疫档、A20 脏档位钳制、A21 非法值、A22 `DIVIDE` 除零。

4. **档位断言（C1）**：`R = 1000` 在默认模式下**合法**且使力量线 `D ≡ 0`；`R ∉ {0,200,400,800,1000}` → 钳到最近档位并 warning（严格模式下拒绝读档）；`R > 1000` → 断言拒绝；`DIVIDE` 备选下 `R = 1000` → 拒绝读档（除零）。
