## 一、伤害与数值

- 力量伤害：`D = (力量 - 护甲) × (1 - 物抗)`，取整 `floor`。
- 破甲伤害：固定值 = 攻方破甲值，无视物抗，直接打护甲池。
- 抗性五档（量子化）：无 0 / 低 200 / 中 400 / 高 800 / 免疫 1000（千分比）。
- 三处取整：伤害 `floor`、倍率连乘 `round_half_up`、命中率 `ceil`。
- `0 < D < 1 点` → 命中率夹在 [1%, 99%]，命中就造成 1 点；`D ≥ 1 点` 必中。
- 力量池归零才阵亡；护甲池归零不死。
- **不能用精力加伤害**：精力只用来付技能费（已删掉早期"投注精力加伤害"整套）。
- 属性表在 `bc_stat.md`（只有表格，不许写散文）；改表后跑 `python tools/make_unit_data.py` 生成 `game/src/core/unit_data.gd`。
- 移动力 / 物抗 / 魔抗 **不可加点**；射程只有远程与投掷手可加点；加点点数无限；重置只清当前角色。

## 四、被动

- **杰拉尔德【箭矢弹反】**：`[2.0, 1.0, 1.0]` 秒三次按键；**只有轮到杰拉尔德自己的回合开始**才把 flag 置 1，弹反一次立刻置 0（一回合射十支箭也只有第一支进 QTE）。散步 = **弹反专用曲线**：`r(t)=0.48·t²`，没有 100% 准确区（2 格 0.03 / 5 格 0.19 / 10 格 0.75 / 20 格 3.0）。
- **阿莱特【蓄势】**：哨兵每摧毁一枚投射物 +1 层（每层 +4 力量）；加在"力量-护甲"那一段（会被抗性减伤，可能仍是 0）；下一发**选普攻选目标**的箭命中后清零；技能与哨兵箭不吃。
- **投掷手【装填】**：回合结束时若没移动过 +2 精力；可与休息叠加（休息共 +4）。
- 弹反 QTE 是 2D `Control` 面板（3D `Label3D` 在暂停时不刷新网格）。

## 五、散步（Spread）

- 普通散步（**AI 的普攻与技能**用）：飞行时间平方；5 格以内完全准；20 格 → 半径 1.5（直径 3）。
- 弹反散步：见上（翻倍 + 无准确区）。

## 七、胜负与回合

- **唯一结束条件：一方老国王阵亡**。英雄死光不算输。
- 英雄无限重生（满血满护甲，10 个回合后回到重生点）。
- 老国王与公主**不进队列**（`no_turn`）。
- 常规模式下**绝不允许同一方连续两回合**（有一处自愈纠错 + 断言）。
- 最后一人连击（保留）：一方只剩 1 个活英雄时，孤军 → 对面每人 → 孤军…；一旦进入就保持。

## 八、AI（`core/ai.gd`）

- 全图视野，无战争迷雾。**敌方整队默认交给 AI**（`gm.ai_enabled`）；`gm.ai_autoplay_player` 是自动演算（两边都 AI）。
- 打分 = 伤害 × 职业权重 × 血量因子 + 距离惩罚；国王 2.6 > 投掷手 1.3 > 弓箭手 1.15 > 近战 1.0 > 沙盒 0.3；并列取随机。
- 决策顺序：能打到的最高分目标（要挪位就挪）→ 技能 → 休息/靠拢。**只有"真能打到"的组合才算攻击**。
- 投掷手：地毯只在"≥2 敌挤在轰炸框里且落点不在敌方哨兵射界"时丢；**轨道空爆是杰拉尔德的技能，投掷手不抢**（技能按 `Skills.skills_for` 判定拥有权）。
- **近战也会用技能**：有轨道空爆的（杰拉尔德 / 敌方镜像）会朝敌方国王头上提前埋标记，但**必须在自己技能的射程（3-20）以内**，并用与玩家完全一致的投掷弹道 + `Spread` 散步（不能太准太远）。
- **阵亡清除一切状态与 buff**（用户口径）：哨兵警戒、蓄势层数、挂起未结算的技能、被动机会记录全部作废；复活回来是"干净"的，不会带着哨兵状态。
- 弓箭手【新增口径】：**身处敌方投掷手射程内、而本回合（含走位）打不到它时 → 直接开哨兵**。
- 远程/投掷：**追求在射程边缘输出**（射程 8 就尽量待在 8 格附近，`EDGE_PENALTY`）；弓箭与投掷共用同一套"锁定 + 会打偏"的落点函数（`Ai.aim_at` → `Spread`）。
- 移动后不能休息（规则），AI 回合必须有收尾，否则卡死。
- AI 阵营的弹反走概率判定（60%），不弹 2D 面板。
- 验证工具：`tools/sim_ai.gd`（两边 AI 自动打完，6 倍速，卡死检测）。

## 九、UI

- 顶栏：轮次 / 当前行动者 / 缩放滑条 / 调试按钮（**没有**精力投注按钮）。
- 最底部常驻细条：沙盒按钮（木刺 ×4、土堆 ×6）+ **队列可视化**（图标 34px，**宽度动态** = 实际人数 × 槽宽；面板本身也只按内容宽度收缩）。
- **左下角只保留队列可视化**：单位详情/加点等所有文本框已按用户要求全部移除（节点不挂进场景树，`ui_` 调用不会崩；属性改动走调试面板）。
- 队列预览必须严格交替：跳过阵亡单位时**不换边**（否则 UI 会出现"同一方连续两回合"的假象）。
- 攻击/移动都要**两次点击确认**（第一次出黄勾）。
- 近战与远程都能**锁定沙盒元素**（木刺/土堆）；锁定的箭一定打得中（哪怕木刺不挡远程）。

- 落点：以瞄准落点为圆心、**半径 4 格的圆内随机 8 个点**（8 发火箭）；每发**直击范围 = 半径 1 格的圆**；伤害由直升机的力量决定。
- 动画：**一次发射两枚**（左手边一枚、右手边一枚），**共四次**，**每次间隔 250ms**。

### 13.3 新弹射物：火箭（炮弹类）
- 模型：直径 **0.37 格**、长 **0.7 格**的圆柱；头部一个半球；尾部侧面每隔 90° 贴一个小直角三角形（共 4 个尾翼）。
- **飞行速度与飞行时间正相关**：初始 **2 格/秒**，飞行 **12 格后到达上限 6 格/秒**（函数由实现者定义）。
- 落地范围**直径 2 格**；同时从落地中心**随机两个方向生成 2 枚破片**。
- 属于**炮弹类**（可被哨兵拦截/惊动哨兵的规则同炮弹）。

### 13.4 被动：坠机
- 力量低于 **21** 时**坠机**（做一个加速下坠动画）。
- 坠机后：以落地点为圆心、**半径 2.5 格**内所有角色受到 **20 力量 + 40 破甲**的炮击伤害（带"降低 50% 物抗"的那种 buff），然后该角色**死亡**。
- 在**皇室竞技场**重生需要 **25 个回合** —— 这种**场景特有参数要写进关卡元数据**（`Level.DEFS`），不要硬编码。

### 13.5 主动技能：俯冲轰炸
- 玩家选定 **20 格以内**的一格作为目标 → 直升机进入**准备状态**（标识方法自定）。
  **要求：敌方 AI 必须能感知这个状态并做出决断**（例如弓箭手据此开哨兵）。
- **下一次轮到它的回合**时，以 **6 格/秒**向选定格**俯冲**，高度由 **2 格均匀降到 0.5 格**。
- 俯冲期间**会受伤、也会触发被动**：
  - 若触发被动 → 模型换成"投掷手普攻同款炮弹但**直径翻倍**"，并**保持触发瞬间的速度沿直线撞地**，按被动口径造伤。
  - 若顺利抵达目标格上方 → **停 0.5 秒并投弹**，投完**原路返回**。
- 投的弹 = 投掷手普攻模型但**直径翻倍**；作用范围**半径 3 格**；**40 破甲 + 20 力量**；和炮击的炮弹一样**不触发哨兵**；动画从直升机底部落到地面，**下落速度与轨道空爆一致**。

### 13.6 场景同步
- 两个现有场景（测试场 / 皇室竞技场）的元数据都要正确收录这个角色（我方 + 镜像），并带上它场景特有的重生回合数。

### 13.7 施工顺序（建议）
1. 数据行（本体 + 镜像）+ 关卡 roster + 场景元数据（重生 25 回合）
2. 悬浮 2 格 / 移动速度两倍 / 普攻耗 4 精力 + 双倍投掷瞄准 + 8 发火箭散射 + 250ms 两次齐射动画
3. 火箭弹射物（模型 + 变速 + 直径 2 格落地 + 2 枚破片）
4. 被动坠机（阈值/动画/2.5 格炮击/25 回合重生）
5. 主动俯冲轰炸（准备状态 + AI 感知接口 + 俯冲/投弹/返航）
6. 建模 + 测试 + 探针

## 十四、统一入口（第 82 轮重构，用户批准）

### 14.1 为什么做
一次"普攻"原本有**四条并行入口**，每加一个角色要在每条入口里各插一个 `if`：
```
拖拽松手 _fire() ／ 点目标 _attack_target_unit() ／ AI 出手 _ai_attack() ／ 受伤收尾
```
漏掉任何一条就出 bug，而且**真实发生过**：
- 直升机火箭只接上拖拽那条 → 点目标 / AI 还在打普通炮弹、不耗精力；
- 坠机只挂在俯冲里 → 正常挨打永远不触发；
- 枪榴弹 AI 分支被一次并发写入冲掉，且没有任何测试能发现（三条入口都没覆盖它）。

### 14.2 普攻：`core/attack_profile.gd` + `battle_scene._perform_basic()`
- `AttackProfile.DEFS`：五种普攻模板 —— `melee` / `arrow` / `burst`（连发：发数与间隔也在这里）/ `shell`（投掷炮弹）/ `salvo`（火箭齐射）。
- 归属表三张：`BY_NAME`（角色名）、`BY_PREFIX`（名字前缀，直升机这一族）、`BY_ROLE`（职业兜底）；镜像 `(E)` 自动继承。
- 每个模板声明 **`basic`（怎么打）+ `aim`（怎么瞄：target / drag / cell）+ `cost`（精力）**。
  直升机的一切数值以**关卡配置 `Level.heli()` 为准**（`basic_cost` 等），表里只写 `"level": "heli"`，**一处来源**。
- `_perform_basic(u, aim, target, placeable, break_armor, guard_acted) -> bool` 是**唯一**出口：
  先查精力（不够就什么都不做、不占行动），再统一置"已行动"、扣精力、刷新属性栏，最后按 `basic` 分派到一个实现函数。
- 三条入口从此只负责"算出打哪里"：`_fire`（拖拽）/ `_attack_target_unit`（点目标）/ `_ai_attack`（AI）。
- **加新角色 = 表里加一行**（需要新玩法时再加一个 basic 实现），三条入口自动同步。
- 模板化的两个自然结果（口径确认）：
  - 打**沙盒道具**（木刺/土堆）也照模板走 —— 投掷手抛炮弹、直升机打火箭、连发打子弹（都给 `target_placeable` 锁定），
    不再出现"投掷手隔着 20 格用近战方式敲掉土堆"这种怪事；
  - 玩家点普攻时若**精力不够**：现在**不占行动**，并把行动菜单还给他（以前会白白吃掉这一回合）。

### 14.3 技能：`Skills.cast/aim` + `battle_scene._perform_skill()`
- 每个技能在 `Skills.DEFS` 里声明两个正交字段：
  - `cast`：`sentry`（点一下）/ `dive`（点一格）/ `carpet` / `grenade` / `marker`（拖拽类）；
  - `aim`：`self` / `cell` / `drag`（UI 按它决定走哪条选目标流程，`_choose_skill` 不再按技能名写 if）。
- `_perform_skill(u, sid, aim, cell) -> bool` 是**唯一**出口，玩家与 AI 都调它；
  扣精力只在这里发生一次（`carpet` 由 `_start_carpet_bomb` 自己扣，入口**不再**重复扣 —— 这是本轮顺手修掉的隐患）。
- 点格子类目标的判定单独成 `_confirm_cell_target(cell)`（越界/超程提示重新点），方便自检直接调用；
  状态旗标 `_cell_targeting`（原 `_dive_targeting`）在取消/回菜单时一并清掉。

### 14.4 被动：受伤钩子表
- `Passives.DEFS` 里声明 `on_damaged: true` 的被动，由 `_after_damage_to_unit()` 依次执行
  `battle_scene._passive_hooks`（id → Callable）中的实现；钩子返回 true = 已接管后续收尾。
- 直升机的【坠机】现在是一条正式被动（`BY_PREFIX` 挂在"俯冲轰炸直升机"前缀上），不再散落在函数里。

### 14.5 顺带修掉的两个隐患
- **AI 付不起的普攻**：`Ai.plan` 现在用 `AttackProfile.cost_of(me)` 过滤；执行端打不出时 `_ai_attack` 会自己结束回合 —— 以前会出现"选了攻击 → 出手被拒 → AI 回合空转到看门狗"。
- **一次技能扣两份精力**（地毯式轰炸）：入口与实现只能有一处扣费。

### 14.6 回合机：空队列不再无限递归（AI 演算里抓到的真 bug）
- 触发条件：**双方英雄同时全灭，而两边老国王都还活着**（国王与公主是 `no_turn`，不进队列）。
  此时 `_next_turn()` 发现队列空 → `_start_round()` → 又是空队列 → `_next_turn()`…，
  无限递归直到栈溢出（实机表现=卡死/崩溃；AI 演算里轮次冲到 1023 才炸）。
- 修法：新增 `_begin_next_round()`。发现"一个能进队列的单位都没有"时**推进 GM 回合边界**
  （英雄复活计时就走在这里），等人回来再开新一轮；连续 200 个边界仍无人可行动才兜底结束战斗。
- 防回归：试玩第 39 节把 10 个英雄全部打死（保留国王），断言轮次不暴涨、边界照常推进、英雄会复活。

### 14.7 防回归（试玩第 38~39 节）
- 5 个代表角色 × 各自允许的入口（拖拽/点目标/AI）打出**完全相同的指纹**（弹种、发数、精力、是否已行动、是否掉血）；
- 精力不足时：不出弹、不占行动，AI 路径必须自己收尾（不许软锁），AI 决策层也不选付不起的普攻；
- 5 个技能 × 3 条路径（共享入口 / AI 入口 / 玩家真实 UI 入口）产生**相同的效果计数**；
- 精力不足时技能不施放、不扣精力；
- 钩子表覆盖所有 `on_damaged` 被动；
- 英雄全灭时回合机不递归、能自我恢复。
