## 一、伤害与数值

- 力量伤害：`D = (力量 - 护甲) × (1 - 物抗)`，取整 `floor`。
- 破甲伤害：固定值 = 攻方破甲值，无视物抗，直接打护甲池。
- 抗性五档（量子化）：无 0 / 低 200 / 中 400 / 高 800 / 免疫 1000（千分比）。
- 三处取整：伤害 `floor`、倍率连乘 `round_half_up`、命中率 `ceil`。
- `0 < D < 1 点` → 命中率夹在 [1%, 99%]，命中就造成 1 点；`D ≥ 1 点` 必中。
- 力量池归零才阵亡；护甲池归零不死。
- **精力不能加伤害**：早期"投入精力加伤害"（1 点 = +2 力量，`ENERGY_POWER_MILLI=2000`）整套**已删除**，
  现在没有任何"拿精力换伤害"的入口。
- **精力用来支付行动费**：技能要精力，**普攻也可能要精力**（直升机的火箭齐射普攻 = 4 精力）。
  出不起就不出手，且**不占行动**（见 §14.2、§九）。
- 属性表在 `bc_stat.md`（只有表格，不许写散文）；改表后跑 `python tools/make_unit_data.py` 生成 `game/src/core/unit_data.gd`。
- 移动力 / 物抗 / 魔抗 **不可加点**；射程只有远程与投掷手可加点；加点点数无限；重置只清当前角色。

- **空爆三维判定**：球心带高度，角色视为竖直圆柱（半径 0.3、高 1.0，**底面 = 该单位的悬停高度 `hover`**）。爆炸范围固定为直径 1 格的球（半径 0.5）。只炸角色，不炸沙盒道具（否则一串炮弹被拦就连锁全炸）。
- **两种"没飞到落点"要分开（第 87 轮）**：**被箭击落** -> 就地**空爆**（一格球）；**飞行中撞到角色** -> **当成在命中处落地**，走和平常落地完全一样的结算（炮弹按 `blast_r` 炸、火箭还要撒 2 枚破片、枪榴弹就地立模型开始计时）。入口只有一个：`battle_scene._land_shell(p, at)`（正常落地也走它）。
- **枪榴弹的例外（第 96 轮）**：枪榴弹在半空**被击落 = 整发作废**（模型直接消失：不落地、不立模型、不登记 GM 计时、不爆炸），和轨道空爆的召唤球一样；
  **落地后**才照旧立模型 + 4 回合计时。`Ballistics.intercept_result(枪榴弹) = ""`。
- 落地爆炸仍是"红圈沾到格子就算命中"（**不看高度轴**：地面爆炸照样打到悬停单位 —— 这是刻意的，否则直升机对范围技能免疫）。
- **例外**：直升机的**投弹**（第 86 轮起）是**三维球**（球心在离地 0.15 格、半径 3 格），所以爬到 4 格以上投弹不会炸到自己。

## 三之二、高度轴（第 83 轮，第 84 轮统一为"纯物理"）

- 角色身体的竖直区间 = **`[hover, hover + 1.0]`**（`Targeting.body_span`）；瞄准一个角色时瞄**身体中心**（`Targeting.aim_height` = 身体底 + 0.5）。
- **身体高度按"它现在真的在哪"算（第 89 轮）**：`Unit.body_y` 是临时高度（-1 = 用 `hover`），爬升轰炸每帧写入 `_place_diving` 的高度。
  `Targeting.body_span / aim_height`、`Damage.air_burst`、哨兵瞄准全部读它 ——
  以前爬到 4 格投弹、身体却还按 `hover=2` 判定，于是被自己的炸弹炸成 21 血（41 - 20）。
- 枪榴弹（炮弹类）**落地**在河面/空场 -> 直接作废（不立模型、不登记 GM 计时）；
  **在半空被击落**则不走地形规则（第 96 轮）：整发直接消失。
- **一切按物理碰撞判定（第 84 轮口径）**：弹道物必须**真的碰到身体**才算命中 ——
  - 从地面角色头顶飞过 -> 不算命中；从悬停 2 格的直升机下面穿过 -> 不算命中；
  - **碰到任何角色（不分敌我）都照常造伤**（友伤保留，只是不再"隔空误伤"站在弹道上的人）；
  - 所以箭矢不再"必定打中挡在弹道上的人"，而是看它飞行高度是否真的扫到身体。
- **炮弹类**（炮弹/火箭/枪榴弹）：撞人判定同样物理；**撞上 = 当成在命中处落地结算**（第 87 轮；枪榴弹 = 在那一格落地开始 4 回合计时）。半空**被箭击落**：炮弹/火箭/巡飞弹走空爆，**枪榴弹整发直接消失**（第 96 轮）。
- 各武器的瞄准高度：弓箭/子弹瞄 `hover+0.5`；哨兵箭瞄触发目标的 `hover+0.5`（拦弹道物时瞄那一发当时的高度）；老国王的加农炮瞄 `hover+0.5`。
- 落地爆炸（红圈沾格）与近战仍然是**格子口径**，不看高度轴 —— 否则悬停单位会对范围技能完全免疫。
  **唯一例外（第 96 轮）**：**近战攻击打不到身体离地的单位**（直升机悬停 2 格、俯冲时 2~4 格）——
  判定 `Targeting.melee_reaches(u, t)`（`t.body_h() > 0` 就够不着），玩家点目标、紫色高亮、`_perform_basic`、AI 决策四处同一口径。

## 四、被动

- **杰拉尔德【箭矢弹反】**：`[2.0, 1.0, 1.0]` 秒三次按键；**只有轮到杰拉尔德自己的回合开始**才把 flag 置 1，弹反一次立刻置 0（一回合射十支箭也只有第一支进 QTE）。散步 = **弹反专用曲线**：`r(t)=0.48·t²`，没有 100% 准确区（2 格 0.03 / 5 格 0.19 / 10 格 0.75 / 20 格 3.0）。**反弹出去的箭吃 75% 力量**（第 93 轮从 25% 改回；`Passives.DEFS["arrow_deflect"]["power_mult"]`，走的还是发射单上的 `power_mult`，先乘再减护甲）。
- **阿莱特【蓄势】**：哨兵每摧毁一枚投射物 +1 层（每层 +4 力量）；加在"力量-护甲"那一段（会被抗性减伤，可能仍是 0）；下一发**选普攻选目标**的箭命中后清零；技能与哨兵箭不吃。
- **投掷手【装填】**：回合结束时若没移动过 +2 精力；可与休息叠加（休息共 +4）。
- 弹反 QTE 是 2D `Control` 面板（3D `Label3D` 在暂停时不刷新网格）。

## 七、胜负与回合

- **胜负条件写进场景元数据（第 97 轮），不同场景相互独立** —— 判定是纯函数 `TurnFlow.check(units, Level.victory(), gm.turn_count)`，入口 `battle_scene._check_over()`。
  - 四种类型：`king`（一方老国王阵亡，**缺省**，也是第 96 轮以前唯一的规则）｜ `annihilate`（一方可行动单位全灭）｜ `survive`（守满 `rounds` 个回合边界）｜ `reach`（有人站进指定格）。
  - 可叠加：`{"type":"king","also":[{"type":"survive","rounds":20,"side":1}]}` —— 任意一条满足就分胜负。
  - 现有两个场景（测试场 / 竞技场）**都在 `Level.DEFS` 里显式声明了** `{"type": "king"}`，不靠隐式缺省。
  - **加场景 / 加玩法都不用改场景侧代码**：改元数据一行；新类型在 `TurnFlow.check_one()` 的 `match` 里加一个分支（约 5~8 行）。
  - 完整契约与扩展示例见 **[`docs/level_campaign.md`](level_campaign.md)**。
- 英雄无限重生（满血满护甲，回到重生点）。**重生等待回合 = 场景元数据**：第 100 轮起**所有场景**统一为
   「**直升机 20 个回合、其余角色 15 个回合**」（`Level.DEFS[<场景>]["respawn_default"] = 15` +
   `respawn_turns = {"俯冲轰炸直升机（不要问那么多）": 20}`）。英雄死光不算输（`king` 模式下）。

- 老国王与公主**不进队列**（`no_turn`）。
- **回合队列（第 87 轮改成"队头模型"）**：双方各一条队列，`[0]` 就是下一个行动的人。
  - 一个回合结束 -> 把刚行动的人**出队再入队尾**（轮转），然后换边（`advance(who)`，必须显式传人：复活会把别人压到队头）。
  - **阵亡 = 当场移出队列**（`TurnQueue.remove`，不是"跳到队尾"）—— 死人不再占位置，整圈也不再因为他变长。
  - **复活 = 压进自己这条队列的队头**（`push_front`；一个回合边界复活多人就压进多个队头元素）—— 下一次轮到自己这方立刻能动。
  - **一方队列空了 -> 自动跳过它的回合**（另一方连续行动），直到有人复活。这就是"复活饥饿"的根：旧实现里死人还占着环形队列的位置，而且一方全灭后对面会一直动、活过来的人排在环的后面永远轮不到。
- 常规模式下**绝不允许同一方连续两回合**（有一处自愈纠错 + 断言）；**例外**：对面队列是空的（全在等复活）时本来就该连续动，纠错会跳过。
- 最后一人连击（保留）：一方只剩 1 个活英雄时，孤军 → 对面每人 → 孤军…；一旦进入就保持。

### 13.5 主动技能：爬升轰炸（原名"俯冲轰炸"，第 86 轮改成爬升）
- 玩家选定 **20 格以内**的一格作为目标 → 直升机进入**准备状态**（标识方法自定）。
  **要求：敌方 AI 必须能感知这个状态并做出决断**（例如弓箭手据此开哨兵）。
- **下一次轮到它的回合**时，以 **2.5 格/秒**（= 悬停移动速度）向选定格飞过去，并**均匀爬升**到 **4 格**。
- **技能移动 = 一次移动（第 89 轮）**：`_dive_begin` 清哨兵闩、`_place_diving` 每帧按真实浮点位置采样 ——
  **从射界外飞进射界会触发哨兵**（以前只有走路的视觉位移会采样，技能飞行完全不惊动哨兵）。
- 途中**会受伤、也会触发被动**：
  - 若触发被动（**力量池被打空**）→ 坠机：模型换成"投掷手普攻同款炮弹但**直径翻倍**"撞地，按被动口径造伤。
  - 若顺利抵达目标格上方 → **停 0.5 秒**，然后**投弹**（炸弹下落 **1 秒**）→
    **在 4 格上等炸弹落地**（第 89 轮新增的 `wait_bomb` 阶段）→ 再**原路返回**并降回悬停高度。
    等弹落地是必须的：身体高度按真实高度算之后，返航途中降到 3 格以下仍会被自己的 3 格球擦到。
- 投的弹 = 投掷手普攻模型但**直径翻倍**；作用范围**半径 3 格的三维球**；**40 破甲 + 20 力量**；
  和炮击的炮弹一样**不触发哨兵**；**爬到 4 格以上所以炸不到自己**（身体高度按真实高度算 + 等弹落地才返航）。

## 十四、统一入口（第 82 轮重构，用户批准）

### 14.1 为什么做
一次"普攻"原本有**四条并行入口**，每加一个角色要在每条入口里各插一个 `if`：
```
拖拽松手 _fire() ／ 点目标 _attack_target_unit() ／ AI 出手 _ai_attack() ／ 受伤收尾
```
漏掉任何一条就出 bug，而且**真实发生过**：
- 直升机火箭只接上拖拽那条 → 点目标 / AI 还在打普通炮弹、不耗精力；
- 坠机只挂在俯冲里 → 正常挨打永远不触发；
- 枪榴弹 AI 分支被一次并发写入冲掉，且没有任何测试能发现（三条入口都没覆盖它）。

### 14.2 普攻：`core/attack_profile.gd` + `battle_scene._perform_basic()`
- `AttackProfile.DEFS`：五种普攻模板 —— `melee` / `arrow` / `burst`（连发：发数与间隔也在这里）/ `shell`（投掷炮弹）/ `salvo`（火箭齐射）。
- 归属表三张：`BY_NAME`（角色名）、`BY_PREFIX`（名字前缀，直升机这一族）、`BY_ROLE`（职业兜底）；镜像 `(E)` 自动继承。
- 每个模板声明 **`basic`（怎么打）+ `aim`（怎么瞄：target / drag / cell）+ `cost`（精力）**。
  直升机的一切数值以**关卡配置 `Level.heli()` 为准**（`basic_cost` 等），表里只写 `"level": "heli"`，**一处来源**。
- `_perform_basic(u, aim, target, placeable, break_armor, guard_acted) -> bool` 是**唯一**出口：
  先查精力（不够就什么都不做、不占行动），再统一置"已行动"、扣精力、刷新属性栏，最后按 `basic` 分派到一个实现函数。
- 三条入口从此只负责"算出打哪里"：`_fire`（拖拽）/ `_attack_target_unit`（点目标）/ `_ai_attack`（AI）。
- **加新角色 = 表里加一行**（需要新玩法时再加一个 basic 实现），三条入口自动同步。
- 模板化的两个自然结果（口径确认）：
  - 打**沙盒道具**（木刺/土堆）也照模板走 —— 投掷手抛炮弹、直升机打火箭、连发打子弹（都给 `target_placeable` 锁定），
    不再出现"投掷手隔着 20 格用近战方式敲掉土堆"这种怪事；
  - 玩家点普攻时若**精力不够**：现在**不占行动**，并把行动菜单还给他（以前会白白吃掉这一回合）。

### 14.3 技能：`Skills.cast/aim` + `battle_scene._perform_skill()`
- 每个技能在 `Skills.DEFS` 里声明两个正交字段：
  - `cast`：`sentry`（点一下）/ `dive`（点一格）/ `carpet` / `grenade` / `marker`（拖拽类）；
  - `aim`：`self` / `cell` / `drag`（UI 按它决定走哪条选目标流程，`_choose_skill` 不再按技能名写 if）。
- `_perform_skill(u, sid, aim, cell) -> bool` 是**唯一**出口，玩家与 AI 都调它；
  扣精力只在这里发生一次（`carpet` 由 `_start_carpet_bomb` 自己扣，入口**不再**重复扣 —— 这是本轮顺手修掉的隐患）。
- 点格子类目标的判定单独成 `_confirm_cell_target(cell)`（越界/超程提示重新点），方便自检直接调用；
  状态旗标 `_cell_targeting`（原 `_dive_targeting`）在取消/回菜单时一并清掉。

### 14.4 被动：受伤钩子表
- `Passives.DEFS` 里声明 `on_damaged: true` 的被动，由 `_after_damage_to_unit()` 依次执行
  `battle_scene._passive_hooks`（id → Callable）中的实现；钩子返回 true = 已接管后续收尾。
- 直升机的【坠机】现在是一条正式被动（`BY_PREFIX` 挂在"俯冲轰炸直升机"前缀上），不再散落在函数里。

### 14.5 顺带修掉的两个隐患
- **AI 付不起的普攻**：`Ai.plan` 现在用 `AttackProfile.cost_of(me)` 过滤；执行端打不出时 `_ai_attack` 会自己结束回合 —— 以前会出现"选了攻击 → 出手被拒 → AI 回合空转到看门狗"。
- **一次技能扣两份精力**（地毯式轰炸）：入口与实现只能有一处扣费。

### 14.6 回合机：空队列不再无限递归（AI 演算里抓到的真 bug）
- 触发条件：**双方英雄同时全灭，而两边老国王都还活着**（国王与公主是 `no_turn`，不进队列）。
  此时 `_next_turn()` 发现队列空 → `_start_round()` → 又是空队列 → `_next_turn()`…，
  无限递归直到栈溢出（实机表现=卡死/崩溃；AI 演算里轮次冲到 1023 才炸）。
- 修法：新增 `_begin_next_round()`。发现"一个能进队列的单位都没有"时**推进 GM 回合边界**
  （英雄复活计时就走在这里），等人回来再开新一轮；连续 200 个边界仍无人可行动才兜底结束战斗。
- 防回归：试玩第 39 节把 10 个英雄全部打死（保留国王），断言轮次不暴涨、边界照常推进、英雄会复活。

### 14.7 防回归（试玩第 38~39 节）
- 5 个代表角色 × 各自允许的入口（拖拽/点目标/AI）打出**完全相同的指纹**（弹种、发数、精力、是否已行动、是否掉血）；
- 精力不足时：不出弹、不占行动，AI 路径必须自己收尾（不许软锁），AI 决策层也不选付不起的普攻；
- 5 个技能 × 3 条路径（共享入口 / AI 入口 / 玩家真实 UI 入口）产生**相同的效果计数**；
- 精力不足时技能不施放、不扣精力；
- 钩子表覆盖所有 `on_damaged` 被动；
- 英雄全灭时回合机不递归、能自我恢复。

### 20.2 制导（Q/E）

### Reaper 的三循环回合（每回合先向前移动一格）

## 二十九、第 100 轮补丁：调试面板的关卡按钮（用户报"找不到 Reaper 关"）

1. 关卡按钮改成**竖排 `VBoxContainer`**，每个按钮 `SIZE_EXPAND_FILL` 占满一行（288px），

2. **关卡名改短**：`name` 只留短名（测试场 48×48 / 皇室竞技场 / Reaper 战），

（c）文字一行放得下、（d）三个按钮 x 一致且 y 递增。

### 3. 激光重做：**一根动态光柱**（旧实现整条删除）
用户原话：
> reaper的激光**完全不应该是现在这种静态超级大范围的**，而是**动态的一个光柱从一个角度向另一个角度移动**；
> 把**光柱理解为直径 0.5 格的圆柱**，**从出发点照向落点**；这个**落点是移动的**，
> **从目标左边一点移动到这个目标上再移动到右边一点**，相当于**半径为 reaper 到目标的距离的圆的一小部分**；
> **角速度一定总动画时间一定**，**伤害与动画期间碰撞到角色的时间相等**；
> **40 格处左右加起来大概扫过 7 格**；**激光有友伤所以一切碰撞都要有伤害**

**旧实现**：`sweep_specs()/slice_specs()/beam_spec()` 生成 **N 条离散的静态光束**（横扫 12 条）
—— 合起来就是"一大片静态区域"，正是用户否定的东西。**整条已删除**
（连同 `battle_scene._point_seg_dist`、`SWEEP_HALF_DEG/SLICE_HALF_DEG` 三处死代码）。

**新实现**：整个动画**只有一根 beam 连续存在**。
- 设 `P` = Reaper 蓝环 `(px, 6, pz)`、`T` = 目标浮点位置、`R = |P.xz − T|`、`axis = normalize(T − P.xz)`
- **横扫**：`half = min(3.5 / max(R, 1.0), 30°)`；`E(t) = P.xz + unit(base + lerp(−half, +half, t)) · R`，
  `base = axis.angle()`。**角速度 ω = 2·half / sec 恒定**，`sec = SWEEP_SEC = 2.0 秒`（120 帧）。
  **弧长固定 7 格 ⇒ 角度随距离变小**：`R=40` 时 `half = 5.013°`、左右合计 **7.000 格** ✓，
  且 `E(0.5)` 精确经过 T（左 → 目标 → 右）。
- **竖切**：`E(t) = T + axis · lerp(+3.5, −3.5, t)` —— 沿中轴**远侧 → 近侧**（43.5 → 40 → 36.5 格），
  `sec = SLICE_SEC = 1.6 秒`。与横扫共用同一套 `u ∈ [−3.5, +3.5]` 参数化。
- **落点用真弧**（不是切线平移）：落点到 P 的距离恒为 R，最大偏差 **0.000004 格**
  （切线平移近似在 R=40 时最大差 0.153 格，R 越小差越多，所以用真弧）。
- **近距离两层保护**：半角封顶 **30°**（R=4 时弧长 4.19 格，不再爆炸）；**R < 1 格**时落点钉在 T 上。
- **`Laser.HIT_R` 0.5 → 0.25**（= 直径 0.5 格，用户口径）。影响面只有 3 处：
  命中判据 `rr = HIT_R + body_r`、视觉圆柱 `top/bottom_radius`、以及探针里那条旧断言。
- **伤害 = 碰撞时长**：每帧重算落点 → `clip_by_terrain` 截断 → 三维判定 → 覆盖谁给谁 +1 帧；
  `life = 总时长`，结束时 `Runner.tick` **统一结算**（帧数 × 2 点/帧，魔法伤害）。
- **友伤**：判定**不做任何阵营过滤**（实测三个友军全被覆盖）。
- ⚠ **一个需要知情的几何后果**：光柱是**斜的**（y 6 → 目标身体高度），三维判定下
  地面身体 `[0, 1]` 只有落在 `0.909R ~ R` 这一段才被碰到 ——
  即**横扫真正威胁的是"目标距离附近那一段弧"**，更近的单位在光束下方不会被碰到
  （这与既有口径"从地面角色头顶飞过不算命中"一致）。要改成"整条线都造伤"就得把
  `Laser.hits_unit` 的三维判定换成水平覆盖判定（一处函数）—— **属于改口径，未动**。

**实测**（`.tmp_for_deepseek/` 临时脚本，27 项 0 失败）：

### 1. 竖切：近 → 远、范围翻倍、速度翻倍（= 每格伤害减半）
`E(t) = T + axis · lerp(−near_len, +far_len, t)` —— **t=0 近侧、t=1 远侧**（原来是远→近）。
- `SLICE_NEAR_LEN = 10.5` / `SLICE_FAR_LEN = 3.5` / `SLICE_NEAR_MARGIN = 1.0`（近端至少离 P 1 格，不许扫到身后）

  `覆盖比例 = far_len / (near_len + far_len)`。所以：

  即：**总行程仍是 14 格（满足"范围翻倍"），只是把 14 格切成"近 10.5 / 远 3.5"**，
  这样覆盖比例从 50% 降到 25%，伤害才真正减半。
  （Lead 独立复核过这条解析式，与实现一致。想回到对称 7/7 只改 `SLICE_NEAR_LEN = 7.0` 一个常量。）

### 3. 子弹散布：**平行圆盘 → 立体球**（用户怀疑得对）
用户问：「你确认现在子弹的散布是立体的球而不是平行的吗？我需要立体球状散步」
**查证结论：他怀疑得对，之前是平行圆盘**：
```
Lunchbox.spread_offset -> Vector2            # 水平圆盘
_lb_fire_wave: aim_pt = base + dir*dist + off # off 只改水平
Ordnance._make_bullet: dir 只拿水平方向、p.y0 = p.y1 = fly_y   # 高度固定
```
→ **子弹永远水平飞，垂直散布恒为 0**。

**改成真正的球内均匀散布**：
- `Spread.ball_offset(R, rng)`：球面均匀 + 半径 `∛u`（**球内**均匀，不是球壳、不是圆盘）
- 新增 `Ordnance.make_cart_bullet_at` / `make_bullet_at`（**共用一个 `_bullet_at`**）：
  瞄准点是 **3D** 的 → 弹道**带俯仰**，但**仍是直线、不受重力**（`arc_scale = 0`）。
  换算：`Projectile.height()` 按整段飞行进度线性插值 y0→y1，而子弹固定飞 32 格 →
  要让它在**目标距离 `dist`** 处正好是瞄准高度，得把 y1 **外推**：
  `y1 = y0 + (to3.y − y0) / (dist / 32)`
- **实测**：`E[r²]/R² = 0.5980`（球内均匀理论 0.600 ｜ 圆盘 0.500 ｜ 球壳 1.000）；
  y 方差 0.1998（旧实现恒为 0）；瞄 12 格外时**15.8% 从头顶飞过、16.3% 打进地里**

修法：地图建好后注视点设为**可到达区中心** `Vector3(PX+PW/2, 0, PY+PH/2)`。
另记：41×65 的地图在 `zoom=15` 时可见范围仅约 27×15 格，对角布局双方跨度 **56 格**
→ 截图时按可到达区最长边放大视野（游戏内仍由玩家滚轮缩放）。

### 2. 「敌方公主」= 误认（截图 + 单位清单双重证据，无代码改动）
Reaper 战截图与单位清单都显示**敌方侧只有 `Reaper`**。用户看到的「公主·左」是**玩家方**那一个
—— 它在 **(2,12)**，俯视下正好落在 Reaper 的**左下方**；它本来也没有哨兵圈
（玩家公主的哨兵来自 `always_sentry` 被动，与敌方无关）。

### 3. 哨兵改用**绝对速度**（用户口径）
用户原话：「**你要检测的不是相对速度而是那个角色的绝对速度！不然车开起来谁都锁！**」
**旧实现为什么错**：`_lb_move_mark` 比较 `u.cell` 在相邻两帧间有没有变，
而 `cell` 是**移动发起那一刻就瞬移**的（走路动画才慢慢走）→
"车自己一移动，相对视角下整个战场都像在动" → **静止友军也被判成在动** → 被索敌。
**新实现**：直接读**走路动画**（`UnitVisual.is_walking()`）—— 天然是绝对运动，
与相机/车在哪无关；停下动画结束即自动 false，不再需要 `until` 窗口去"猜"。
删掉已无用的 `MOVE_HOLD_SEC`。

### 4. 哨兵能打**炮弹类飞行物**（用户口径）
**目标抽象**（唯一出入口）：角色 -> 它的名字；炮弹 -> **`"P:<id>"`**。
新增 `_lb_target_label(x)` / `_lb_live_target(u, label)`（返回 `{alive, in_range, moving, pos, y}`）。
索敌收集追加「**敌方发射的炮弹类**（`Ballistics.is_shell_class`）∧ 24 格内」；
炮弹恒为"在动"（停下就等于落地，那时已不是合法目标）。**误伤仍然保留**（开火不做阵营过滤）。
★ **顺带修掉一处逻辑不一致**：原 `moving_now` 算的是**旧锁** `lock_u`，
却拿它去门**新选出来的** `tgt` —— 换目标那一帧必然误判；现在统一按最终选中的 `want` 重算。

### 5. 子弹地板碰撞（75% 消失 / 25% 反弹）
- **判定**（`projectile_field.step`，节点更新后、出界判定前）：
  `p.is_bullet_class() and prev.y > 0.0 and cur.y <= 0.0` —— **线段穿越**，不是点采样
  （12 格/秒 × 一帧 ≈ 0.2 格，点采样会漏）
- **75% 消失** → `kill("landed_on_ground")` + `_report(EV_FLOOR, p)`。
  ⚠ **不能用 `EV_LANDED`**：那个在 sink 里是**炮弹落地结算**（会触发爆炸），子弹不该炸。
  ⚠ 新增独立的 **`EV_FLOOR`**（而不是复用 `EV_OUT`）：后续处理一样是"直接移除、无爆炸"，
  但**文案不同** —— 撞地却写"飞到边界"会误导（战斗日志用户看得见）。
- **25% 反弹** → `mirror_about_floor()`：**y 关于 0 镜像**，水平/速度/寿命不变
  → 沿**新的直线段**向上飞，**`arc_scale` 保持 0（不引入重力）**；上限 **1 次**
  （用户只要求"25% 反弹"，没要求乒乓；再弹会延长存活、放大跨图误伤）
- **随机源注入**：`projectile_field` 是 `RefCounted`、**没有宿主 `_st`** →
  `setup(..., p_rng)` 注入（缺省退化成场自己的固定种子流，老调用点不会崩）；
  Lead 改调用点 `field.setup(self, gm, sink.arrow_hit_check, rng)` → 与全局同一股随机流、同种子可复现
- **概率实测（Lead 独立复核，403000 次样本）**：
  | 样本 | 反弹比例 |
  |---|---|
  | 独立流 A（场景 rng，200000 次） | **25.028%** |
  | 独立流 B（另一颗种子，200000 次） | **24.984%** |
  | 端到端真打 4000 发俯冲弹穿地 | **24.18%** |
  | **聚合 403000 次** | **24.96% : 75.04%** （期望 25 : 75，偏差 0.04%） |
  （施工者的 1000 发样本给出 27.1% —— 那是 1000 发样本的正常波动，2σ ≈ ±2.7%；
  Lead 用大样本复核后确认**阈值实现正确**。）
- 周边不受影响：箭矢/炮弹/巡飞弹 `is_bullet_class == false`，`bounces` 全 0、行为逐字未变。
## 四十、第 109 轮：7 条

### 1. 车普攻 0 精力不放 —— **Lead 上轮漏改的第二个闸**（真 bug）
用户原话：「**你确定移除了车的普攻的精力消耗吗？为什么现在 0 精力选择完目标后普攻不会释放？**」
**根因**：第 108 轮 Lead 加了 `AttackProfile.COST_BY_NAME` 的**按名覆盖**（车 0 / 直升机 4），
但 `basic_attack.perform_basic` 里读的是 **模板里的原始 cost**：
```gdscript
var prof := AttackProfile.for_unit(u)
var cost := int(prof["cost"])          # ← 绕过按名覆盖；车与直升机共用 BASIC_SALVO -> 仍是 4
```
→ 车即使被覆盖成 0，这里仍按"4 精力"判定 → **0 精力时普攻被静默拒绝**（不置已行动、不结束回合，看起来"点了没反应"）。
**修法**：一律走 `AttackProfile.cost_of(u)`（它是"这一次普攻扣多少"的唯一来源）。
**同类第二处**：`AttackProfile.describe()` 也用模板原始 cost → 详情栏会显示"4 精力"与实际自相矛盾，一并改成 `cost_of`。

### 2. 召唤模板甲的"远程"= **Alette**（用户澄清，Lead 修）
用户原话：「你**错误地理解**了我说的第一个**两个近战一个远程**的刷兵模板，**远程指的不是公主而是阿莱特**」
`Reaper.SUMMON_KITS[0].names`：`["Gerald","Gerald","公主·左"]` → **`["Gerald","Gerald","Alette"]`**。
（`公主·左` 是 `no_turn` 的固定炮台 —— 这正是用户此前"看到敌方公主在 Reaper 脚底下"的误认来源。）

### 3. 巡飞弹发射器挪到**车尾**
用户原话：「发射器现在被**藏在炮管底下**；请把它挪到**车的尾部**（即现在是 x 方向，我需要它在 z 方向）」
`root.position`：`(0.30, ROOF_Y, 0.30)` → **`(0.0, ROOF_Y, -0.50)`**（`x` 居中 = 不再压炮管轴线；
`z` 为负 = 车尾）。约束依据：发射器坐在**车顶面**上，顶面 z ∈ ±0.700 → 底座箱 0.30 占 `z[-0.65,-0.35]` ✅。
与炮塔轴线（`TURRET_X = 0`）**z 间距 0.5 格**；归属仍是 `BodyRoot`（转底盘时跟着转，炮管不动）。
顺带给它稳定名字 `LoiterLauncher` + 门面 `t_loiter_root()`。
> ⚠ 施工者给了一条**几何上限**的诚实提醒：炮管扫掠半径 ≈0.92 **大于**车顶半长 0.700，
> 所以**在车顶范围内不可能完全逃出扫掠圈**；当前 z=-0.50 时炮管朝正后方会从上方经过，
> 但**净空 0.27 格不干涉**（棱柱下沿 1.66 vs 发射器顶 1.39）。要"彻底不被压"需让发射器**探出车尾** —— 造型决策。

### 4. 移除车的**反应延迟**，只保留方向机延迟
`Lunchbox.REACT_SEC`：**0.5 → 0.0**（`sentry.tick` 里 `react >= REACT_SEC` 在 0 时首帧即真 →
对准即可开火）。延迟完全由**双机转速**承担（方向机 20°/s、高低机 5°/s，转到位才开火）。

### 5. 方向机转速翻倍
`Lunchbox.TRAVERSE_DEG_PER_SEC`：**10 → 20**（用户只说了方向机，**高低机 5°/s 不动**）。

### 6. 炮管初始状态 = **指向车头**（仅复活时）
`_lb_state(u)` 新建状态时 `aim.theta = 90.0`（= 网格 +y = 车头，与 `set_body_yaw` 同一套约定）。
用户口径：「只是**复活时**的状态，后续改变后**不会自动恢复**」→ 所以**不每帧重置**，
额外加 `_lb_forget_state(u)`：在 `turn_runner` 的**两处复活路径**（`on_revive_timeout` / `revive_hero`）
清掉该单位的双机/热量/锁定状态 → 下次 `_lb_state` 重建时 theta 回到 90°。
（`_lb_states` 原本**从不清空**，所以不主动清就不会复位。）

### 7. 行进中开火位置绑定**当前炮口**（Lead 修）
用户原话：「尝试让车在**行进中触发哨兵时开火位置与当前炮管口的位置绑定**，
不要现在车还在开呢子弹就已经在移动**目的地**往外冒了」
**根因**：`_lb_center(u)` 用的是 **`u.cell`（逻辑格）**，而逻辑格是**移动发起那一刻就瞬移**的
（真正在走的是**视觉位置**）→ 车还在半路，炮口/发射点已经算在**目的地**了。
**修法**：改用**视觉位置** `GridMath.unit_pos(u)`（= `visual.position.x/z`），
并沿**当前车体朝向**推 1 格得到车体中心（锚点是 1×2 的前半格；车体转向后那个偏移也要跟着转）。
这样 `_lb_center` 的**全部 8 处使用者**（炮口、哨兵测距、齐射两处、技能瞄准…）统一跟着"车现在真正在哪"。

### 8. Reaper 召唤落点必须在**碰撞体之外**
用户原话：「将 REAPER **召唤的重生的**移到 REAPER **碰撞体积外**：现在召唤出来的**投掷手会在其内部开火然后直接大额伤害 REAPER**」
**根因**：`summon_cells()` 的螺旋外扩**从 `r = 1` 开始**，而 `Reaper.body_r = 3` →
`r = 1/2/3` 的落点**全在身体内部**（切比雪夫环 `r` 的欧氏距离 ∈ `[r, r√2]`，`r=1` 时最小 **1.0 < 3**）。
**修法**：`r_start = ceil(body_r) + 1`（= 4，环内最小欧氏距离 4.0 > 3 ✅）**再加欧氏过滤**
`>= body_r + SUMMON_CLEARANCE(1.0)`（防止"方形螺旋的边中点贴到圆柱表面"漏网）；
余量 1.0 的理由：召唤物体半径 0.3 → 边缘离 Reaper 表面还有 0.7 格。
**退化策略**：严格档（半径 ≤ 12）→ 放宽档（余量 0.5、半径 ≤ 20）→ 仍不满就返回已有落点
（调用方会打印实际落点数，**不会静默少召**）；循环上界固定 → **不可能死循环**。
**端到端回归**（用户 bug 的直接测试）：走正式入口真召唤 → 找到刚生成的投掷手（距 Reaper **4.47 格**）
→ 用正式普攻入口朝 20 格外开一炮 → 推进 3.5 秒飞完落地 → **Reaper 力量池全程 999 → 999 不变** ✅
